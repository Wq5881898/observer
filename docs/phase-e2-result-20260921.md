# E2 系统补充通知与去重

状态：实现和自动测试完成；Windows 通知权限、免打扰及实际声音待实机点验，阶段 E 未关闭。

## 行为与接口

用户最新确认：系统通知只用于定时任务到点和启动失败；专注违规只保留声音和窗口提示，姿态保留原柔和提示及 300 秒冷却。窗口新增“定时任务系统通知（到点及启动失败）”开关，默认开启，用 QSettings 保存在各数据目录 desktop.ini，关闭后不调用系统通知接口，不影响计划和计分。

到点信号在模型准备之前发出；启动失败通知在失败状态入库后发出。每次执行尝试使用任务 ID 与单调时间标识，分别去重到点/失败通知；手动开始不发任务通知。关闭时收到的通知不在重新开启后重放。任务通知不是违规 action，不使用其交付账本；schema 保持不变。

Qt 主线程按 action ID 在本次进程生命周期内去重，先登记后呈现，同一动作重复信号不会重复横幅、声音、系统通知或确认。ID 集合保留到窗口销毁，不因恢复窗口清空；其内存随本次运行的提醒数增长，长期资源测试需包含该项。跨进程继续沿用 D 不重放历史提醒的行为。

`mark_notification` 仍表示专注提醒的应用内呈现结果，应用内失败也不改发系统通知。任务系统通道的状态仅显示在窗口底部，未增加持久化的分通道账本。没有增加自动重试以免重复打扰。

系统状态区分不可用、提交失败、已提交；“已提交”不表示 Windows 展示、用户看见或已读。`supportsMessages()` 不能证明用户通知权限开启，界面明确说明 Windows 设置可能阻止通知。本轮不新增声音调用，但系统通知声音由 Windows 控制，是否与现有短音叠加须实机检查。

上述能力限制依据 [Qt QSystemTrayIcon 官方文档](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QSystemTrayIcon.html)。

## 自动验证

`tests/test_desktop_notifications.py` 当前九项通过，覆盖专注和姿态不发系统通知、动作去重、任务通知失败隔离、提交状态与点击恢复、不可用降级、开关持久化与关闭期间不重放、定时到点及启动失败真实工作线程信号、手动开始不通知。
