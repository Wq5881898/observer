# D 测试取证与正式取证需求

日期：2026-09-19  
状态：项目所有者已确认，先写文档后实现。  
适用范围：离开屏幕、可见手机和离席三个计分信号；不改变事件成立门槛、合并提醒、违规时间并集或评分。

## 1. 目标

开发测试期间需要看到违规候选从出现、持续到恢复的画面序列，以便判断误判、漏判和信号波动。正式使用仍坚持最少保存原则，不连续录像，也不按固定周期保存正常画面。

## 2. 测试取证开关

专注页增加“测试取证（违规期间每2秒截图）”开关。该开关仅在开发版界面显示，默认关闭；正式发布时可隐藏入口，底层默认值保持关闭。

测试取证开启且“保存事件截图”开启时：

1. 任一计分信号首次进入违规候选便保存首帧；
2. 候选、成立或恢复迟滞期间每2秒最多保存一张；
3. 所有相关信号恢复后保存结束帧并停止；
4. 离屏、手机和离席在同一行为链中重叠时共用一组图片，不为每个信号重复保存相同时间点；
5. 即使候选最终未达到成立门槛，测试图片仍保留并标记为“未达到成立门槛”，用于分析阈值和模型波动；
6. 暂停、计划休息、结束、断流或中断会结束当前取证序列，不跨边界连接。

## 3. 正式取证

测试取证关闭且“保存事件截图”开启时：

1. 候选开始时只在内存暂存首帧；
2. 候选达到门槛并形成合并专注事件后，才把首帧写入本地证据目录；
3. 事件恢复时再保存一张结束帧；
4. 未达到门槛的候选不写入磁盘；
5. 多个候选前后衔接时，首帧必须来自最终实际成立的信号；更早但未成立的其他候选不能代替该首帧；
6. 统一姿态事件继续保持每个成立事件最多一张图片，不进入高频测试序列；旧会话的人体工学健康事件保持原样。

## 4. 查看与数据边界

同一事件可关联多张图片。事件列表显示图片数量；右侧预览提供上一张、下一张，并显示序号、截图类型、会话内时间、当时信号、事件ID、原图尺寸和SHA-256。测试候选也可在本轮与历史复核中查看。

每张图片继续使用独立ID、原子写入、SHA-256、路径边界验证和错误状态。现有旧图片迁移后保留为单张历史证据。所有图片继续受500MB总配额、30天保留期、单会话删除和全部删除约束。测试取证不保存视频、不保存正常时段画面，也不改变计分结果。
