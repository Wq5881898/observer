## 本次实现

新增 RuntimeWatch 比较相邻工作循环的单调时间和墙上时间。超过 10 秒的运行停顿，或两时钟增量相差超过 5 秒，按连续性失效处理。检测覆盖循环恢复及视觉读取成功/失败返回，不声称能区分睡眠、设备阻塞和手动调时。

发现异常时先于自动到时结束和新观测处理执行：运行中会话在最后已计账时点调用既有 source_gap，清空尚未完成的证据缓存，再通过原结束路径保存为 interrupted，释放摄像头，窗口提示重新开始。停顿期间不连接前后违规区间，覆盖率沿用 D 的不可观测处理。计划休息中的会话同样中断；手动暂停保持暂停。既有事件与已落盘证据保留，不使用恢复后的帧补充停顿前证据。

使用现有 SessionService 接口，未修改 schema、评分公式、规则门槛或核心模块。10 秒为桌面运行健康检测阈值，不是行为规则阈值。较慢的正常模型启动/继续过程不计作观测中断。

## 故障边界补强（2026-09-22）

实际摄像头启动和一次自动重连现都要在限定等待内取得新鲜帧，不能仅凭驱动句柄打开就宣称恢复。无校准的 3 秒视觉预热若画面中断，会在建立会话前失败并释放摄像头/模型；重连即使重新出帧，若过程超过运行连续性阈值，会保存并中断会话，不显示“已恢复”。保留一次重连上限、原有规则断点和评分语义。

新增针对预热断帧、重连无新帧、旧帧/取消、慢重连的故障注入测试；全套自动测试 326 项通过。用户要求后续集中实机测试或抽检，故此处不声称真实 Windows 睡眠和设备掉线已通过，也不再追加分钟级资源门。永久阻塞的原生驱动调用仍是现有工作线程架构的已知边界，隔离触发条件沿用 [E3 隔离决策](phase-e3-isolation-decision-20260922.md)。

## Windows 电源事件入口（2026-09-22）

桌面入口现安装 Qt 原生消息过滤器，接收 Windows `WM_POWERBROADCAST` 的挂起（`PBT_APMSUSPEND`）与自动唤醒（`PBT_APMRESUMEAUTOMATIC`）消息。只在 UI 回调中设置线程安全标记，工作线程于下一个安全点走既有连续性失效路径；不在原生回调中操作 SQLite、摄像头或模型。自动唤醒后可能跟随的用户唤醒消息不重复处理。退出事件循环时移除过滤器。原有双时钟检测保留作漏发消息和非 Windows 平台的回退。

活动观察或计划休息遇到该事件，保存为 `interrupted`，不把事件前后观测连成连续违规；手动暂停保持暂停。消息只能说明系统电源状态转换，不区分睡眠和休眠。模拟原生 MSG 与真实 Qt 工作线程测试、全套 330 项自动测试通过；尚未执行笔记本真实合盖/唤醒点验，E3 不据此宣称验收通过。按项目所有者要求，不运行新的分钟级资源门。
