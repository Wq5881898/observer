# Observer 阶段 C 基准：感知能力验证与个人校准

版本：0.2
日期：2026-08-30
状态：已批准；推荐默认值作为待验证假设

## 1. 阶段目标

阶段 C 要回答的不是“模型能不能跑”，而是“在目标用户、目标电脑和约定使用环境中，Observer 能否以可重复、可度量、不过度误报的方式产生以下四类信号”：

1. 人是否在摄像头有效区域内；
2. 手机是否被持续手持，而不是仅仅出现在桌面上；
3. 上半身是否持续偏离个人舒适中立基线；
4. 双眼/头部方向是否持续离开已校准的主屏允许区域。

本阶段结束时，`attention_away` 和 `posture_deviation` 不再固定为 `unknown`；手机、在席、姿势和注意力均有真实场景指标、已知限制和明确回退路线。

## 2. 范围

### 2.1 进入本阶段

- 观测质量门：亮度、模糊、Face/Pose/眼部/肩部可见性、结果新鲜度和矛盾检测；
- 从 MediaPipe 结果提取版本化、归一化的注意力与姿势特征；
- 20–30 秒姿势中立基线校准，使用中位数和 MAD 等稳健统计量；
- 单主屏 17 点注意力校准和 8 个独立验证点；
- EfficientDet 手机检测、手腕几何关系、候选跟踪和检测后短时升频；
- 引导式 CLI/轻量校准画面、人工标签、JSONL 测量记录和汇总报告；
- 调参集与留出验收集严格分开；
- 单元测试、集成测试、真实设备场景测试和 60 分钟感知管线稳定性测试；
- 将经过校准的信号接回现有 `ObservationFusion`，保持规则引擎与模型解耦。

### 2.2 不进入本阶段

- SQLite、Agenda、正式会话数据库；
- 正式 PySide6 主界面、托盘、声音和浮层提醒；
- 最终证据生命周期和会话报告；
- Windows 安装包、开机启动和自动更新；
- 多显示器、外接/内置摄像头自动切换；
- 身份识别、云端推理、连续视频保存；
- 医学级姿势结论或精确到屏幕文字的注视点；
- 训练新的深度模型。

这些内容分别进入 D、E、F 阶段。阶段 C 只提供可靠的感知信号、校准档案和验证证据。

## 3. 产品语义

### 3.1 在席

Face 或上半身 Pose 只要有一个高质量、新鲜结果，就认为人在席。只有摄像头正常且两者都持续为空，才产生离席候选。锁屏、睡眠、计划休息和主动暂停属于后续会话上下文豁免，不是视觉模型职责。

### 3.2 手持手机

`cell phone` 框本身不是违规。手机与可见手腕/手部持续接近或重叠，才产生 `phone_held` 候选。手机在桌面、遥控器、计算器或黑色笔记本不能被当作手持手机。手机和手都离开有效取景区时输出 `unknown`，不能推断用户没有使用手机。

### 3.3 姿势偏离

“合规姿势”指相对用户自己舒适中立姿势的稳定包络，不表示唯一或医学正确姿势。候选特征包括肩线倾斜、脸/头相对肩中心偏移、头部 pitch/roll/yaw、脸部或肩宽尺度变化、髋部可见时的躯干倾角。默认需要至少两个独立特征组持续越界，避免把伸展和短暂调整当成违规。

### 3.4 屏幕注意力

目标是区分“在已校准主屏允许区域”与“明显持续离开屏幕”，不是精确眼动。输入优先使用虹膜在眼眶中的相对位置、头部方向、脸部位置和尺度。任务允许查看纸质资料、键盘或第二屏属于后续 Agenda 规则豁免，不改变本阶段的基础分类语义。

## 4. 推荐技术方案

| 决策 | 推荐方案 | 理由 |
| --- | --- | --- |
| 校准交互 | 使用现有 OpenCV 创建临时全屏校准窗口；正式 UI 留到 E 阶段 | 不提前引入大型 UI 依赖，仍能准确显示屏幕点位 |
| 注意力校准 | 17 点逐点中位数，NumPy Ridge 3.0 轻量回归，8 个未参与拟合的内部点验证 | 真人 tuning 证明 9 个位置不足以约束 9 个特征加截距；Ridge 3.0 在当前未见点达到 0.171 且未明显压缩边缘范围 |
| 姿势基线 | 35 秒中立姿势，前 5 秒稳定、后 30 秒采样；中位数、MAD 和分位数形成个人包络 | 首次实测表明 25 秒不足以稳定取得 75 个有效 Pose 样本；延长 5 秒但不降低质量门 |
| 质量门 | 图像亮度/模糊 + landmarks 可见性 + 结果新鲜度 + 特征完整度 | 先判断是否可观测，避免把摄像头问题算成违规 |
| 手机检测 | 先保留 EfficientDet-Lite0 int8；检测到候选后升到 burst FPS；跨帧中心距离/IoU 平滑 | 已在目标电脑验证资源充足，避免同时常驻第二个检测器 |
| 手机手部关系 | 先使用 Pose 手腕；只有留出集证明无法区分时才增加 Hand Landmarker | 控制 CPU 和依赖复杂度 |
| 模型升级 | EfficientDet 调整仍未过线时，才比较 YOLO11n ONNX/OpenVINO | 以验收失败触发升级，不做无目标探索 |
| 校准存储 | 版本化 JSON 档案，包含设备/分辨率指纹和派生统计量；位于 `data/` 且不提交 Git | C 阶段不提前建设 SQLite，同时保留可迁移数据契约 |
| 验证记录 | JSONL 保存标签、派生指标、置信度和时间；不保存连续视频 | 可重算指标，又符合最少数据原则 |
| 证据图 | 建议仅保存误判或边界案例的代表帧，每个 trial 最多 1 张，本地 7 天 | 对调试有价值，同时限制隐私暴露；需项目所有者批准 |

### 4.1 最小充分实现原则

批准上述方案不表示必须永久保留全部细节。阶段 C 遵循以下限制：

- 先实现能形成可靠测量闭环的最小版本，不建立通用插件框架、复杂工作流引擎或尚无消费者的抽象层；
- 9 点/17 点注意力校准、单特征/多特征姿势判断、手机升频/平滑应尽量通过同一批派生特征离线对照，不为每个实验复制一套运行管线；
- Hand Landmarker、YOLO11n、L2CS/ONNX 只有当前路线未过硬门槛且证据能指出瓶颈时才实现；
- 任何新增依赖、后台线程、配置项和持久化字段都必须对应一个已批准需求或可量化验收指标；
- 阶段验收不仅评价准确率和性能，还要填写 `docs/phase-c-validation-handoff.md` 的复杂度评分，给出保留、简化、删除或延期结论；
- 被证明没有收益的设计应在阶段 C 结束前移除，而不是以“未来可能需要”为由长期保留。

## 5. 模块边界

建议新增或调整的职责如下，最终文件名可以在不改变边界的前提下微调：

```text
MediaPipe adapters
        │ raw landmarks / boxes / timestamps
        ▼
feature extraction ──→ quality gate
        │                    │
        ├── posture features ├── observable / unknown reason
        ├── attention features
        └── phone + wrist features
        │
        ▼
calibration profiles + evaluators
        │
        ▼
ObservationFusion
        │ away / phone_held / posture_deviation / attention_away
        ▼
existing SustainedRule and PenaltyLedger

labeled trial recorder ──→ validation metrics/report
```

约束：

- 特征提取层不得产生提醒或扣分；
- 校准评估器不得导入规则状态机；
- `ObservationFusion` 只消费标准化结果，不保存图像；
- 验证记录器不得改变预测结果；
- 校准档案必须有 `schema_version`，未知版本拒绝静默加载；
- 档案至少绑定摄像头索引、采集分辨率、主屏分辨率和创建时间；环境指纹不匹配时必须要求重新校准或明确确认。

## 6. 数据契约

### 6.1 校准档案

至少包含：

- `schema_version`、`profile_id`、创建时间；
- 摄像头索引、帧尺寸、镜像约定；
- 主屏尺寸和缩放信息；
- 质量门阈值及校准期有效覆盖率；
- 姿势特征的中位数、MAD/分位数和最低可用样本数；
- 注意力特征定义、回归系数、校准误差和验证误差；
- 实现版本和特征版本。

档案默认不保存完整脸部 landmarks、姓名或原始图像。

### 6.2 验证 trial

至少包含：

- `trial_id`、场景 ID、数据集角色（tuning/holdout）；
- 人工真值、开始/结束单调时间；
- 预测状态、置信度、派生指标和 unknown 原因；
- 告警候选产生时间和相对延迟；
- 可观测覆盖率；
- 可选证据文件的相对路径和 SHA-256。

## 7. 实施工作包

批准后按以下顺序连续实施，不在中间重新讨论已批准事项：

1. **C0 契约和测试夹具**：建立校准、质量、特征、trial 和报告数据结构及合成测试；
2. **C1 特征与质量门**：输出可解释的标准化特征和 `unknown` 原因；
3. **C2 姿势校准**：完成引导采样、档案序列化、偏离评估和合成/回放测试；
4. **C3 注意力校准**：完成 17 点交互、轻量回归、8 点验证误差和区域分类；
5. **C4 手机真实场景工具**：完成标签引导、候选升频/平滑和场景记录；
6. **C5 融合接入**：让四类信号进入现有 Observation 和规则引擎，保持 unknown 安全语义；
7. **C6 调参集运行**：只用 tuning trials 调整阈值；
8. **C7 留出集验收**：冻结阈值后运行 holdout，不允许根据留出结果继续调参；
9. **C8 稳定性与报告**：运行 60 分钟感知管线、汇总指标、限制和资源数据；
10. **C9 阶段提交**：自动化测试通过，更新阶段报告，提交并推送 GitHub。

真实校准和场景 trial 需要用户按屏幕提示完成动作；“一次性完成”表示批准后不再暂停讨论方案，但不表示可以在无人配合下伪造真实标签。

## 8. 验收门槛

### 8.1 功能与安全

- 校准档案能创建、验证、加载、拒绝损坏或环境不匹配的内容；
- 缺失、过期、低质量或矛盾信号全部输出 `unknown`，不得输出违规；
- 不录制连续视频；未开启证据策略时不写任何帧；
- 调参集和留出集在目录、trial ID 和报告中可明确区分；
- 同一冻结档案和输入记录产生确定性相同结果。

### 8.2 个人目标设备指标

| 能力 | 阶段 C 通过线 |
| --- | --- |
| 在席/离席事件 | F1 ≥ 0.95 |
| 注意力离开事件 | precision ≥ 0.85，recall 建议 ≥ 0.75 |
| 姿势偏离事件 | precision ≥ 0.85，recall 建议 ≥ 0.75 |
| 持续手持手机事件 | precision ≥ 0.90，recall ≥ 0.80；前提是手机和手处于有效取景范围 |
| 正常场景误报 | ≤ 2 次/小时 |
| 计时误差 | 95 分位 ≤ 1.5 秒 |
| 正常条件有效观测覆盖率 | ≥ 90% |
| CPU | 60 分钟平均 ≤ 15%，P95 ≤ 25% |
| 内存 | 稳态 ≤ 500 MB，一小时增长 ≤ 50 MB |
| 摄像头 | 不积压帧；临时失败后能退出或恢复并给出明确状态 |

precision 是硬门槛，因为频繁误报会破坏产品可信度。建议 recall 是阶段判断的重要指标；如果 precision 达标但 recall 未达标，只能“有条件通过”，并明确可检测范围。

## 9. 失败回退路线

### 9.1 注意力未过线

1. 检查校准质量、镜像约定、眼部可见性和特征稳定性；
2. 调整特征、正则化和允许区域，但只能用 tuning 集；
3. 若仍失败，比较 L2CS/ONNX 的准确率、CPU 和许可；
4. 若仍不合格，产品能力降级为“明显头部离开屏幕方向”，不宣称眼睛始终在屏幕附近。

### 9.2 姿势未过线

1. 调整质量门、稳健包络和多特征投票；
2. 将能力限制为可靠的前倾/侧倾类别；
3. 不为追求 recall 降低 precision 门槛或作医学结论。

### 9.3 手机未过线

1. 调整 EfficientDet 置信度、ROI、升频和平滑；
2. 若问题来自手腕不可见，再验证 Hand Landmarker；
3. 若问题来自手机漏检，再比较 YOLO11n ONNX/OpenVINO；
4. 阶段 C 不训练新模型。确需训练时必须单独立项并重新评估硬件、数据和许可。

## 10. 已确认决策

| ID | 决策 | 推荐默认值 | 未确认的影响 |
| --- | --- | --- | --- |
| C-D01 | 目标使用布局 | ThinkPad 内置摄像头 + 内置主屏，单用户，正常桌面光照 | 外接显示器/摄像头需独立档案和额外测试 |
| C-D02 | 误判证据图 | 仅 errors，单 trial 最多 1 张，本地保留 7 天，Git 忽略 | 完全不存图会降低误判复核能力；全存不符合最少数据原则 |
| C-D03 | 注意力校准 | 17 点拟合、8 点独立验证、Ridge 3.0；环境指纹变化后重校准 | 旧 9 点方案在真人 tuning 中出现参数数超过独立目标数的欠约束问题；17 点增加约 11 秒交互，不增加运行开销 |
| C-D04 | 手机时间产品契约 | 20 秒温和提醒、60 秒开始扣分、120 秒强提醒 | 当前配置的 10 秒单阈值与预研建议不一致；D/E 阶段需升级为分级阈值 |
| C-D05 | 眼镜与常用外观 | 按用户真实常用状态验收；眼镜/无眼镜差异明显时分档案 | 不纳入常用状态会让注意力指标失真 |
| C-D06 | 纸质资料/键盘 | C 阶段标注为离开屏幕；D 阶段允许按 Agenda 豁免 | 若在 C 中直接算合规，会混淆基础分类和任务规则 |

项目所有者于 2026-08-30 确认全部采用推荐默认值。C-D05 在真实校准开始前按用户当天的日常眼镜状态记录，不为尚未发生的外观组合预建档案。所有默认值都可以依据真实问题分析后调整，但变更必须记录原因和前后指标。

## 11. 阶段完成定义

只有同时满足以下条件，阶段 C 才能提交“通过”结论：

- 本文件和验证协议已经批准；
- 所有 C0–C9 工作包完成；
- 自动化测试和真实留出集均有可复现结果；
- 硬验收线全部通过，或明确标记为“有条件通过”并得到项目所有者接受；
- 生成 `docs/phase-c-result.md`，不包含人脸图像或个人原始特征；
- 完成设计必要性/复杂度评分，清理被证明无收益的实现；
- 代码、测试和文档已提交并推送私有 GitHub；
- 项目所有者确认阶段结论。
