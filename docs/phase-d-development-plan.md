| --- | --- |

## 5. SQLite 最小数据模型

优先标准库 sqlite3、显式 SQL 与顺序迁移脚本，避免本阶段额外 ORM/通用插件框架。采用短事务、单写入路径和外键；WAL 与忙等待参数在目标 Windows 环境测试。模型推理、截图编码和通知不放在数据库事务内。

| 表 | 核心字段/职责 |
| --- | --- |
| schema_migrations | 版本、应用时间 |
| tasks | 标题、时区、计划时长、单次时间/每周重复、开始提醒提前量、休息策略、启用状态、规则策略引用 |
| task_occurrences | task_id、scheduled_at_utc、状态、关联 session_id；任务+计划时刻唯一 |
| rule_policies | 版本化规则与豁免配置；已开始会话使用不可变快照 |
| sessions | 任务实例、UTC 开始/结束、终止原因、规则/模型/代码/校准快照 |
| session_intervals | 监控/暂停/休息/故障区间，以及各信号连续状态的聚合区间 |
| events | 会话、规则、事件起止、状态、触发阈值与解释；保留软/硬类型 |
| actions | 稳定 action_id、事件 ID、kind、事件内序号、发生时刻；唯一约束避免重复处理 |
| penalty_ledger | action_id 唯一、实际扣分、被抑制原因、策略版本 |
| evidence | 事件、相对路径、时间、哈希、到期、大小、写入/删除状态 |
| settings | 保留期、图像开关、配额、默认时区及 schema 化配置 |

每个输入样本不永久逐帧落库：连续状态聚合成区间，事件保留必要统计。报告读取持久化事实，不依赖仍在内存的 PenaltyLedger。历史 C JSONL 不批量自动导入产品库，测试回放使用明确适配入口。

## 6. 关键行为约定

### 会话与恢复

状态为 waiting_for_source、monitoring、paused、break、ended、interrupted。任务到点先建立会话，再预检必要源。硬信号所需模型/摄像头不可用则等待，不计作用户离席；软信号校准缺失可禁用该能力并明确展示，不强迫每次任务重做 17 点校准。

暂停、休息、豁免生效时终止对应待触发计时；已有事件按原因关闭。恢复后从新鲜观测重新计时，不能把暂停前后的手机片段拼成持续违规。采集故障区间保留为 unknown，已激活事件遵循现有 unknown grace，不补记断流时间。

进程重启后把未完成会话标记 interrupted，保存已经提交的扣分；不跨进程连接 monotonic 时间，不把停机时间算违规，不自动恢复摄像头。用户可选择继续任务并创建关联的新会话。UTC 用于存储日期，monotonic 用于本次进程计时。

### Agenda

实现没有引入APScheduler。SQLite业务数据库是计划模板、任务实例与执行状态的唯一来源；产品工作线程按有限滚动范围补齐实例并检查到期任务，避免第二套调度持久化和额外依赖。

建议默认：单次和每周指定星期/本地时间；运行中 60 秒内的调度迟到允许启动一次，超过窗口标为 missed 并提示用户手动开始；进程重启不自动补开历史摄像头会话。DST 不存在的本地时刻跳过并标注，重复时刻只执行第一次。修改任务只影响未来实例，已开始会话快照不变。

同一时刻只运行一个摄像头会话。发生重叠任务时记 conflict 并提示选择，不暗中中止当前任务、不并行抢摄像头。到计划结束时自动结束；用户可提前结束或在结束前延长。休息由 SessionService 定时进入和退出，CLI 可以取消/延长。

### 计分与覆盖率

新会话使用时间比例评分，不恢复预研的attention/posture加权公式，也不再使用100分减3分/5分账本。离屏、可见手机和离席独立达到持续门槛后进入同一个合并专注事件；分项事实与区间全部保留，总违规秒数取时间并集。原姿态与人体工学候选在产品层合并为一个零计分“姿态”事件。旧会话保留原账本和分数，不追溯重算。

幂等持久化以action ID和合并事件ID为准；事件、分项区间、时间并集和action在同一事务提交。先提交再通知；通知投递单独标记，重试不产生第二次提醒或重复时间。事务失败时停止该会话后续计分并进入故障状态。

每信号分别统计eligible、valid和violation时长：暂停与计划休息从计分时长排除，监控期断流仍在计分时长内但降低coverage，对应豁免信号不参与本次评分。coverage=valid/eligible。总分有效性采用本次启用计分信号覆盖率的最小值；coverage低于80%或没有可计分时段时显示“证据不足”，底层区间仍可查。

### 证据与删除

产品数据默认保留30天，截图默认关闭，全局图像配额500 MB。开启后每个合并专注事件保存正式首尾图，统一姿态事件最多一张。指标本地保存，不存连续视频或完整landmarks。照片满额或写入失败只记录证据异常，不阻断事件与评分。保留期底层有设置，当前极简界面不提供编辑。

证据先写临时文件后原子改名，索引跟踪 pending/ready/failed；启动时处理孤儿临时文件和缺失索引。清理按 pending_delete→删除文件→删除关联记录执行，可重试并诚实报告未删项，不声称跨数据库/文件系统原子事务。路径必须解析后仍位于 data/product/evidence；符号链接/目录联接越界拒绝处理。

“删除全部产品数据”只作用于 data/product，不触碰 C 研究数据、模型、源码或校准原件。产品清理不代替用户对历史调试录像的删除决定。

## 7. 运行入口与最终演示

当前入口为 `observer product gui/run/task/retry/cancel/history/images/data/purge/delete-session/delete-all/check`。桌面窗口维护重复计划和会话控制；报告只在界面和控制台查看，不导出。托盘、开机启动和跨终端控制当前会话留给E/F。没有本机IPC或网络HTTP服务；SQLite短事务负责非会话管理，唯一运行窗口通过运行锁拥有摄像头和当前会话。

验收演示：创建短任务 → 到点启动 → 离屏与手机重叠形成一个合并事件和一次提醒 → 暂停期间不计时 → 恢复并结束 → 重启后时间比例报告与区间一致 → 删除会话后图片和记录一致消失。真实适配继续复用C冻结Observation，不在产品层另造感知算法。

## 8. 测试与阶段完成条件

确定性测试使用可控时钟和临时 SQLite，不要求用户为状态机长时间保持动作。必须覆盖：

1. 触发前/触发时/恢复/unknown/豁免/暂停边界；软规则持续异常仍零计分影响；
2. 重复提交、通知重试、重启、事务回滚与唯一执行实例；
3. 任务编辑/取消、时区/DST、迟到、重叠及计划休息；
4. 有效覆盖率边界、零样本、分项时长与账本重建；
5. 图片关闭、写入失败、配额满、删除失败重试与路径越界；
