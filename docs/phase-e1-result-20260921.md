## 已实现

- `desktop_tray.py` 提供 Qt 托盘图标、显示、暂停/继续、结束及退出菜单；只发出 UI 信号，不引用产品数据库或摄像头。
- `ObserverWindow` 统一处理关闭隐藏、恢复、明确退出、无托盘降级和隐藏期间托盘失效恢复；窗口底部始终显示行为说明与退出按钮。
- 托盘和窗口共享原来的命令队列、忙碌门控和状态快照，最小化保留任务栏入口。
- 明确退出通过 `requestInterruption()` 请求工作线程收尾，`exit_ready` 只在工作线程结束后发出；`launch` 保持 Qt 事件循环运行到收尾完成，并对事件循环外部退出提供等待清理路径。
- 工作线程关闭前阻止新的模型预热；等待已有预热资源释放后关闭 SQLite 和运行锁，模型关闭异常时仍清理数据库及锁。
- 后台运行文案与计划说明已更新。系统通知、睡眠恢复、推理进程隔离和自动单实例唤醒尚未实现。

## 接口与所有权

`ProductStore`、`SessionService`、`RuntimeLock` 和视觉源继续由单个 `DesktopWorker` 拥有。Qt 主线程新增的托盘只提交现有命令并更新 UI。

`BackgroundCameraPreloader.close()` 新增可选参数 `wait=False`；桌面退出使用 `wait=True`，在产品工作线程等待预热线程。默认调用行为保持原样，不增加依赖，也不重复加载模型。

本轮未修改 `product.py`、`focus.py`、`rules.py`、schema/迁移、模型配置、评分、事件或证据策略。已有 D 修改完整保留，未创建 Git 提交或重置工作区。

新增测试使用真实 Qt 控件、事件循环、产品工作线程、SQLite 和运行锁，以模拟源和替代的操作系统托盘可用状态隔离硬件。覆盖：

1. 关闭/恢复重复三次、最小化恢复、隐藏时持续取观测且只有一个所有者；
2. 托盘暂停/继续/结束与窗口共用忙碌门控，重复点击不创建多次会话；
3. 隐藏时定时任务开始并自动完成；
4. 明确退出等待慢速资源关闭，UI 计时器仍运行、锁保持到释放结束、退出信号只发一次；
5. 无托盘时关闭退出，以及隐藏后托盘失效恢复；
6. 工作线程停止后恢复可见窗口；
7. 启动期间隐藏不取消，明确退出才取消且不创建会话；
8. 预热期间退出等待模型释放，预热线程结束后才释放运行锁；
9. 模型释放异常仍释放数据库和运行锁；
10. 隐藏时第二个窗口被拒绝，第二个窗口未触及数据库；
11. 独立进程运行真实 Qt 事件循环，隐藏后退出进程返回且锁可重取；
12. 预热关闭等待与禁止关闭后回调。

测试过程曾发现一处测试替身签名没有接受模型准备参数，修正后通过；不是产品运行缺陷。生成截图和编译缓存的首次沙箱写入遭权限拒绝，随后通过受审批执行完成；未更改系统权限或 Git 全局配置。

## 尚未验证与边界

- 未进行 Windows 托盘实际点击、Explorer 重启或通知权限点验。托盘暂时消失的自动恢复目前由故障注入覆盖。
- 未打开真实摄像头，未运行 E 的 60 分钟后台资源门，未执行系统睡眠/唤醒或操作系统强杀。
- 原生模型/驱动若永久阻塞，当前退出会等待，不能保证有限秒数内退出；进程隔离和资源测量由 E3 决定。
- 本轮没有加入自动单实例唤醒；第二次启动仍按 D 运行锁拒绝。

## 后续顺序

E2 增加系统补充提醒与去重。设计时必须区分“调用系统通知接口”与“系统实际展示/用户已读”：Qt 托盘通知不能据一次调用推断送达。D 的 `mark_notification` 目前只保存动作级交付状态，不能把系统通道失败覆盖为应用内提醒失败，也不能静默扩展为多个通道的持久化账本。若确需 schema 改变，先按交接约定提出接口说明。
