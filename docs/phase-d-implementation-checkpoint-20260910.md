## 2. 极简首轮时的批准调整

项目所有者要求功能和界面极简、按需扩展，并明确报告暂不导出。以下是2026-09-10首轮切片的实施边界；2026-09-13批准的D8～D10已恢复其中的重复计划、简化休息和最小豁免，详见本文末和范围复核文档：

- 只保留单次任务，不实现每周重复、复杂休息策略、编辑和复杂冲突仲裁；
- 以运行窗口中的轻量轮询代替APScheduler和后台服务；
- 使用六张直接服务现有消费者的SQLite表，不建设原计划中的通用策略、occurrence、区间和独立账本层；
- 只提供数据库可重建的窗口/CLI摘要，不导出JSON或HTML，不做趋势图；
- 不建设IPC、托盘、自启动、安装包和云能力；
- PySide6基础窗口因项目所有者选择而从E提前，保留为一个窗口，没有摄像头预览；
- 提醒仅做Windows声音、任务栏闪烁和持久横幅；完整系统通知与托盘仍属于E的可选扩展。

## 3. 实施中的偏离修正

首次真实产品会话没有profile，导致软信号不可用。产品入口现自动采用本机默认profile，并提供 `--no-profile` 显式退出；界面直接展示能力状态。

首次提醒只更新瞬时窗口文字，离屏用户不易察觉。现改为异步Windows警示音、任务栏闪烁及保留到下一会话的红色横幅。摘要同时展示软信号累计异常时间，并说明累计不等于连续事件。

自然会话曾只有6.3秒累计attention violation，引发“D是否遗漏C模型”的合理质疑。随后以相同profile、代码和YOLO负载执行中心、左屏外、恢复、右屏外对照，四项全通过。由此确认模型接线正确；产品再增加即时“屏内/屏外候选/不可判断”和实际会话头姿基线身份记录，避免只凭最终事件猜测当前可观测性。

## 4. 简要经验

- 可选能力必须在界面明确显示是否启用，不能只在命令参数或会话JSON中体现。
- 面向离屏用户的提醒必须在事件结束后仍可发现；瞬时文字和普通Qt蜂鸣不足。
- 受控C试验与自然产品会话的准备条件不同。怀疑模型回归时应先做同代码、同profile、同负载的最小对照，再决定是否改阈值。
- 17点校准、同会话头姿基线、实时分类和8秒事件门是四个不同层次；界面应区分“屏外候选”和“已经触发提醒”。
- 极简不等于省略故障与隐私边界。单实例、事务回滚、unknown安全、资源释放和受限删除仍是主体功能。

## 5. 后续实施顺序

保持功能和界面极简，但继续建设能支持以后按需增加功能的内部基础：

1. D1 可升级数据地基：加入明确、可测试、保留现有记录的数据库迁移机制；
2. D2 任务与会话可靠性：补齐重启、迟到、冲突、摄像头启动失败和异常恢复的产品状态；
3. D3 事件与提醒交付：让持久化事件、界面提醒和失败状态可核对，避免只看最终分数；
4. D4 隐私与数据管理：在极简界面提供必要的记录查看、单次删除和截图状态说明；
5. D5 真实运行加固：进程异常、长期运行、CPU/内存和数据库负载；60分钟门按所有者当前决定暂缓；
6. D6 阶段对齐：锁定C最终冻结身份并完成真实短回归；这只解决输入一致性，不提前给出D验收结论；
7. D7 综合验收：汇总D3/D4真人结果、D5长期资源结论和故障/时序回归，再由项目所有者确认。

该顺序记录D1～D7极简首轮。其后的D8～D10已经恢复重复计划、简化休息、最小豁免和今日摘要；报告导出、趋势图、复杂规则设置和托盘仍不进入当前范围。

### D3 当前进度

schema v5在action记录上加入提醒交付状态。新提醒先随事件事务保存为 `pending`，桌面窗口或控制台实际呈现后更新为 `delivered`，呈现失败保存为 `failed` 和简短原因；v4及更早的历史提醒因无法追溯而迁移为 `unknown`。摘要只增加一行“提醒交付”，显示已确认、未确认和历史未知次数。

交付状态更新是幂等的，失败后再确认成功不会新增action或改变分数、扣分账本。提示音/界面呈现或交付状态写回失败被限制在提醒通道，不停止当前摄像头会话。会话结束或下次启动发现遗留活动会话时，仍为pending的提醒会标记failed并说明“退出前未确认”；迟到的成功确认仍可安全覆盖该状态。全套212项自动测试通过。D3基本账本与退出时序已覆盖，实际Windows提醒的v5交付记录随下一轮真人短测确认。

### D5 当前进度

产品桌面和控制台会话现复用已有资源采样器，每5秒采集一次本进程CPU和内存，并在会话开始与结束各强制取样。单次会话样本上限为20000，超过当前24小时时长上限所需的约17280个周期样本；会话结束后只把平均CPU、P95 CPU、内存峰值、可计算时的小时增长和预算判断汇总写入schema v6，不保存逐点资源数据。

现有会话摘要只增加一行CPU和内存原始结果，不增加页面或图表。采样器初始化或运行失败会保存在汇总的 `sampling_error`，不会中断摄像头、规则处理或计分。工作线程发生未被局部处理的异常时，当前会话会保存为 `interrupted`、记录具体错误、写入已取得的资源汇总并释放数据源；故障注入已验证这条路径。

新增真实子进程强制终止回归：子进程先取得产品运行锁并提交活动会话，再用非正常进程出口终止，不执行Python清理逻辑；父进程随后成功重新取得同一锁，并把遗留会话恢复为带明确原因的 `interrupted`，资源汇总诚实保持为空，停机时间没有补算。新增 `product check` 短时负载入口，默认运行15秒真实摄像头，也可加 `--demo`；它复用正式SessionService、视觉源和资源采样，但数据库位于自动删除的临时目录，不污染产品历史。

成功路径也在临时目录验证：一个会话、一张事件图和一个待执行任务被删除，截图开关设置继续保留，数据库结构仍可重新打开。

跨终端任务路径此前只由同进程测试间接覆盖。新增真实CLI子进程回归：主进程持有运行锁、保持活动会话和SQLite连接时，第二进程成功写入一个未来任务；运行端立即读取到同一pending记录，活动会话状态不受影响。这确认运行锁不会误伤已经承诺的跨终端短操作。

全量删除逻辑从CLI内的直接SQL循环收进 `ProductStore.delete_all()`。执行删除前会先验证所有持久化证据路径及其临时文件路径；任一记录越界时整批拒绝，不会先删掉排在前面的正常会话。专项测试构造两个会话及一个越界索引，确认失败后两个会话和产品目录外文件都保持原样。文件系统中途故障仍受既有“可重试但不声称跨文件/数据库原子”边界约束。

自动保留期清理原先会让单个证据路径或文件删除异常终止整个运行线程。现改为逐会话隔离：失败会话保留并把原因写入现有证据异常状态，其余到期会话继续清理，SQLite写入错误仍会上抛并触发既有安全中断。专项测试确认一个越界会话不会阻止另一个安全会话过期删除，产品目录外文件保持不变。

数据库启动校验补入产品设置语义。除SQLite、外键、结构和迁移账本外，现要求 `images` 为布尔值，`retention_days` 为1至3650的整数；缺失、非法JSON、错误类型或越界值均在打开摄像头前明确拒绝。专项测试覆盖非法JSON和零天保留期，避免损坏设置到自动清理或界面刷新时才暴露。

迁移账本校验原先只检查最大版本，当前版本为6但中间记录缺失时仍可能通过。现要求账本精确等于连续的v1至v6序列；专项测试删除v3记录后确认数据库在启动时被拒绝。

单会话约束校验原先只确认索引名称存在，同名普通索引也能通过。现核对完整索引定义，要求它是建立在固定表达式上的唯一部分索引，并只覆盖monitoring和paused状态。专项测试用同名普通索引替换后确认启动被拒绝，避免数据库静默允许两个活动会话。

外键检查原先只能发现当前已有的孤儿数据，无法发现表定义中的外键已被移除。现核对sessions到tasks以及totals/actions/evidence到sessions的四条关系，并验证三个子表仍使用级联删除。专项测试重建一个字段相同但没有外键的evidence表，确认空表状态也会在启动时被拒绝。
