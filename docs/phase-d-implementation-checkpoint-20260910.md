## 2. 相对原D方案的批准调整

项目所有者要求功能和界面极简、按需扩展，并明确报告暂不导出。以下调整属于批准后的范围收缩，不是遗漏：

- 只保留单次任务，不实现每周重复、复杂休息策略、编辑和复杂冲突仲裁；
- 以运行窗口中的轻量轮询代替APScheduler和后台服务；
- 使用六张直接服务现有消费者的SQLite表，不建设原计划中的通用策略、occurrence、区间和独立账本层；
- 只提供数据库可重建的窗口/CLI摘要，不导出JSON或HTML，不做趋势图；
- 不建设IPC、托盘、自启动、安装包和云能力；
- PySide6基础窗口因项目所有者选择而从E提前，保留为一个窗口，没有摄像头预览；
- 提醒仅做Windows声音、任务栏闪烁和持久横幅；完整系统通知与托盘仍属于E的可选扩展。

## 3. 实施中的偏离修正

首次真实产品会话没有profile，导致软信号不可用。产品入口现自动采用本机默认profile，并提供 `--no-profile` 显式退出；界面直接展示能力状态。

首次提醒只更新瞬时窗口文字，离屏用户不易察觉。现改为异步Windows警示音、任务栏闪烁及保留到下一会话的红色横幅。摘要同时展示软信号累计异常时间，并说明累计不等于连续事件。

自然会话曾只有6.3秒累计attention violation，引发“D是否遗漏C模型”的合理质疑。随后以相同profile、代码和YOLO负载执行中心、左屏外、恢复、右屏外对照，四项全通过。由此确认模型接线正确；产品再增加即时“屏内/屏外候选/不可判断”和实际会话头姿基线身份记录，避免只凭最终事件猜测当前可观测性。

## 4. 简要经验

- 可选能力必须在界面明确显示是否启用，不能只在命令参数或会话JSON中体现。
- 面向离屏用户的提醒必须在事件结束后仍可发现；瞬时文字和普通Qt蜂鸣不足。
- 受控C试验与自然产品会话的准备条件不同。怀疑模型回归时应先做同代码、同profile、同负载的最小对照，再决定是否改阈值。
- 17点校准、同会话头姿基线、实时分类和8秒事件门是四个不同层次；界面应区分“屏外候选”和“已经触发提醒”。
- 极简不等于省略故障与隐私边界。单实例、事务回滚、unknown安全、资源释放和受限删除仍是主体功能。

## 5. 后续实施顺序

保持功能和界面极简，但继续建设能支持以后按需增加功能的内部基础：

1. D1 可升级数据地基：加入明确、可测试、保留现有记录的数据库迁移机制；
2. D2 任务与会话可靠性：补齐重启、迟到、冲突、摄像头启动失败和异常恢复的产品状态；
3. D3 事件与提醒交付：让持久化事件、界面提醒和失败状态可核对，避免只看最终分数；
4. D4 隐私与数据管理：在极简界面提供必要的记录查看、单次删除和截图状态说明；
5. D5 真实运行加固：断流恢复、长期运行、CPU/内存和数据库负载；60分钟门按所有者当前决定暂缓；
6. D6 阶段对齐：使用C最终冻结身份完成真实回归，再讨论D验收结论。

报告导出、趋势图、每周重复任务、复杂规则设置和托盘仍不进入当前极简范围；只有实际需求出现时再增加。

### D1 当前进度

已完成第一步迁移安全基础：新库使用schema v4并记录v1至v4迁移，旧库升级前按原版本自动生成可读备份，再在短事务中逐版本升级。迁移失败完整回滚，步骤跳级/停滞、未来未知版本和当前版本的缺表、缺字段、缺唯一索引、账本不一致都会拒绝打开。自动测试覆盖历史数据保留、v1→v2→v3→v4连续升级、v2和v3真实字段变更、备份、故障回滚与损坏结构拒绝。

目标电脑产品库另有首次升级前保存的 `observer-v1-before-migration-20260910.sqlite3`，并从6个会话、1个任务无损升级为同样的6/1记录。当前运行窗口仍持有v2库；目标产品库会在下次使用新代码打开时先生成v2备份，再顺序升级到v4。D1仍需继续拆分目前集中在 `product.py` 的仓储边界，因此这里只记为D1首个切片完成。

### D2 当前进度

已修复重启迟到补偿与实现不一致的问题。控制台和桌面现在共用存储层过期规则：迟到不超过60秒仍可启动，超过60秒标为 `missed`；桌面自动启动回归覆盖迟到30秒、唯一会话和正常结束。控制台恢复失败时也会关闭已经打开的新摄像头源。

schema v3增加任务错误原因。定时任务启动失败、迟到、冲突和异常中断会持久化简短原因，桌面计划列表与CLI可直接显示；专项测试证明摄像头启动失败后没有会话、失败原因在重开数据库后仍存在。

冲突、失败和错过的任务可在无活动会话时立即重试或取消，已经建立过会话的任务保持唯一执行。摄像头读取异常会保存当前会话为 `interrupted` 并释放设备，桌面与控制台本身继续运行；schema v4保存中断原因并在历史摘要显示。

摄像头源现在允许短暂不可观测，并在连续约5秒无新鲜画面后执行一次有界自动重连。重连只替换采集线程，保留已加载模型和会话校准基线；规则连续性在断流点重置，间隔不计为有效观测。成功后继续原会话，失败或第二次断流则明确中断。全套207项自动测试通过。D2基本恢复路径已覆盖，下一步转入D3事件与提醒交付；进程级崩溃和长期压力仍在D5处理。
