## 4. F 首轮目标及推荐路线

先做 Windows x64、Python 3.11 的 PyInstaller `onedir` 内部候选包，沿用项目既定选型。文件夹版便于检查资源收集；应先验证它，再考虑 `onefile`。[PyInstaller 官方工作模式说明](https://pyinstaller.org/en/stable/operating-mode.html)

首轮交付应包括：可重复构建脚本、受版本控制的 spec／必要 hooks、可双击启动 GUI 的候选目录、版本和文件哈希清单、最短启动说明、打包测试记录。构建工具版本另行锁定，避免将打包工具混入运行时需求；不把开发环境整体复制进发行目录。

优先生成便于观察错误的诊断候选，再验证无控制台 GUI 候选。无控制台时不能依赖 stdout／stderr 提示致命错误，必须有可定位的本地日志或界面错误。当前没有打包入口、spec 或成功 EXE 的验证证据；不要在报告中提前填写已构建。

3. 新打包文件尽量集中于 `packaging/`、构建脚本及 F 文档；涉及 `desktop.py`、`product_cli.py` 等共享文件，先重新读取并确认没有另一任务同时修改。
4. 不重写评分、schema／迁移、规则、事件合并、证据保存、C 模型和校准语义；不为打包重新引入摄像头子进程或双份模型。必要接线变更必须附自动回归。
