# Observer 阶段 C 复杂度与止损评审

日期：2026-09-10
状态：冻结候选评审完成；后续盲测和长测已通过，阶段 C 已关闭

## 1. 评审原则

本评审不追求普通摄像头感知的所有边界都正确。阶段 C 的目标是让 MVP 在当前
电脑和主要使用条件下处理绝大多数清晰异常，同时把不可可靠观察的情况安全地
降为 `unknown` 或软信号。评审沿用既有标准：必要性 `N` 和复杂度负担 `C` 均为
0～3；结论为 `keep`、`simplify`、`remove` 或 `defer`。

冻结后的产品分层如下：

| 信号 | 产品级别 | 默认后果 |
| --- | --- | --- |
| 在席/离席 | 硬信号 | 连续 20 秒后提醒并扣分 |
| 清晰可见的持续手机 | 硬信号 | 连续 10 秒后提醒并扣分 |
| 明显持续离开屏幕 | 粗粒度软信号 | 可提醒，不扣效率分 |
| 精细 gaze 坐标 | 诊断信号 | 不直接提醒或扣分 |
| 姿态偏差 | 健康软信号 | 可提醒，不扣效率分 |
| 人体工学风险 | 独立健康软信号 | 可提醒，不扣效率分 |
| 低质量、严重遮挡、超出有效取景 | 不可判定 | `unknown`，不扣分 |

## 2. 最终复杂度结论

| 设计 | N | C | 结论 | 依据与边界 |
| --- | ---: | ---: | --- | --- |
| OpenCV/DirectShow 最新帧采集与断流诊断 | 3 | 1 | keep | 摄像头占用、无有效图像和正常采集均有明确结果；是全部能力的基础 |
| 画质门与非黑色镜头遮挡识别 | 3 | 1 | keep | 手指遮镜头可能呈暗棕色而非黑色；真实事件测试中完全遮挡为 100% `unknown` |
| Face + 可信 Pose + Person 的在席融合 | 3 | 2 | keep | Pose-only 会把椅背当人，Face-only 又会把纸张遮脸当离席；冻结事件链两类反例均通过 |
| YOLO S304 单类手机检测 | 2 | 2 | keep（限定范围） | 清晰完整手机及主要低位场景已有多轮证据；持续事件复测在 10.000 秒触发。只承诺有效取景内清晰可见手机 |
| 低频 EfficientDet Person 补充探针 | 3 | 1 | keep | YOLO 单类模型不含 person；1 Hz 补充探针保住遮脸在席语义，短测资源仍在预算内 |
| 手机候选跨帧保留与升频 | 2 | 1 | keep | 原始检测存在短空档；最终盲测发现清晰手机原始检测有约1.88秒空档，因此保留窗口由1.5秒有限调整为2.0秒；自然使用和盲测中的短假框仍远低于10秒提醒线 |
| 极低露边/严重遮挡手机专项训练 | 1 | 3 | defer | 边际收益下降且会引入相似物体误报；MVP 允许漏检或 `unknown`，不再追加 Sxxx 补丁训练 |
| ROI/边缘裁剪二次推理 | 0 | 2 | remove（未实施） | 已明确拒绝新增；会扩大推理、规则和测试面，不是 C 阶段必要条件 |
| 17 点 gaze 回归 | 1 | 2 | simplify | 既有校准和特征保留用于软判断与研究，但不再把精确屏幕坐标当硬扣分依据，也不重建模型 |
| 同会话头姿基线与粗头眼融合 | 2 | 1 | keep（软信号） | 能处理会话位姿差异；六批联合调参召回约 91.77%、特异度约 99.01%，但单场景波动大，因此只作软提醒 |
| 姿态中位数/MAD、多组证据 | 1 | 1 | simplify/keep | 能解释明显侧倾和托头，但自然距离变化造成较多逐帧异常；保留趋势和健康提示，取消效率扣分 |
| 人体工学独立信号 | 2 | 1 | keep | 将持续歪头、肩部不平等健康风险与注意力分开，避免效率和健康双重处罚；禁止医学诊断表述 |
| 关键帧证据、SHA-256 与到期索引 | 3 | 2 | keep | 多次帮助确认误判根因；默认不录连续视频，证据受数量和保留期限制 |
| 调试全程录像 | 1 | 1 | simplify | 仅在明确诊断时临时启用并人工复核；正式运行和 60 分钟长测默认关闭 |
| 大规模边界测试矩阵 | 1 | 3 | defer | 历史上帮助发现逻辑错误，但继续扩大会造成过度测试；冻结后只保留硬信号最小盲测和自然长测 |
| tuning/holdout 数据隔离 | 3 | 1 | keep | 防止用调参数据冒充泛化结论；当前最后事件复测仍诚实标为 tuning |

## 3. 已停止的工作

- 不再继续 YOLO 补丁式训练或增加训练轮数；
- 不新增 ROI、边缘 crop 或第二套手机规则；
- 不重建 attention，不重新做 17 点可视化校准；
- 不追逐眼镜反光、极端头眼补偿、跨设备与极低露边的逐项完美；
- 不再扩大 P0 场景矩阵；旧数据作为研究证据保留，不作为必须重跑清单；
- 不在阶段 C 提前开发 Agenda、SQLite、托盘或正式通知 UI。

## 4. 评审时列出的关闭门（现已全部完成）

以下清单保留评审当时的验收口径；最终结果见 `phase-c-window-handoff.md`，12/12硬信号盲测和60分钟无录像长测均已通过，阶段C已关闭。

1. 一轮 2～3 分钟、无模型结果反馈的冻结硬信号盲测；
2. 一次有效的 60 分钟无调试录像自然长测；
3. 对长测报告核对 CPU 平均/P95、内存增长、摄像头失败、异常区间和证据；
4. 最终自动化与模型/配置哈希复核；
5. 项目所有者确认阶段结论后，更新总体计划并冻结 Git 版本。

如果最小盲测或长测出现阻塞性错误，只修复对应根因并补失败场景；不恢复已停止的
全量矩阵。若仅出现已披露的软信号波动、短于事件门槛的假框或极端边界漏检，记录
为限制，不阻塞阶段 C 最终通过。
