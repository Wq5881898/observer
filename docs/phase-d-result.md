## D2 任务与会话可靠性启动

启动审查发现控制台和桌面此前会把所有已经到点的待执行任务立即标为 `missed`，实际绕过了计划中“重启后迟到不超过60秒仍启动一次”的补偿规则。现将过期判断集中为同一存储接口：迟到小于或等于60秒的任务保持可执行，超过60秒才标为错过；桌面回归测试证明迟到30秒的任务会自动补启动、只建立一个会话并正常结束。

控制台恢复路径同时补齐资源释放：若摄像头已重新打开但会话恢复失败，会立即关闭新源，不占用设备。schema v3为任务增加可选错误原因；定时任务启动失败、迟到、冲突和异常中断会保存简短原因，重开桌面后仍能在原计划列表直接看到，不增加页面或设置项。

冲突、失败和错过的任务现在可在无活动会话时立即重试，也可直接取消；已经建立过会话的任务仍禁止重复执行。桌面计划页只增加一个“重试选中任务”按钮，CLI增加 `product retry <任务ID>`。摄像头读取异常不再终止整个桌面或控制台：当前会话保存为 `interrupted`、释放设备，运行入口继续可用。schema v4进一步保存会话中断原因，点击历史摘要仍能查看。

真实摄像头源增加有界断流恢复：短暂无帧继续输出安全 `unknown`；连续约5秒没有新鲜帧后，同一会话最多自动重连一次，只重建摄像头采集线程，复用已经加载的模型和会话校准基线。断流时显式打断规则连续性，间隔计入eligible但不计valid，不能把断流前后的违规片段拼成一次处罚。重连成功继续原会话；失败或再次断流则保存中断原因、释放设备，桌面/控制台仍可开始新会话。全套207项自动测试通过，`pip check` 和 `git diff --check` 通过。D2基本恢复路径已覆盖，更复杂的进程级崩溃恢复仍未完成。

## D3 事件与提醒交付启动

schema v5为action增加 `delivery_state`、`delivery_attempted` 和 `delivery_error`。新alert先与事件一起落库为 `pending`；桌面或控制台实际呈现后确认 `delivered`，呈现失败记录 `failed` 和原因。旧库无法证明历史提醒当时是否显示，因此v4→v5迁移将旧alert标为 `unknown`，没有伪造成功。

桌面使用带action ID的提醒信号，呈现完成后再回写；摘要显示已确认、未确认和历史状态未知次数。交付状态可从失败幂等更新为成功，重复确认不产生新action，分数和扣分保持不变。声音、界面呈现或交付状态写回错误只影响提醒通道，不中止当前会话。

会话结束或下次启动发现遗留活动会话时，仍为pending的提醒会标记failed并保存“退出前未确认”原因；迟到到达的界面成功确认仍可转为delivered。由此覆盖事件事务提交后、界面确认前退出的窗口，不自动重放旧提醒。全套212项自动测试、`pip check` 和 `git diff --check` 通过。D3基本工程路径已覆盖，v5实际Windows提醒交付记录仍需随下一轮真人短测确认。

## D5 真实运行加固启动

桌面和控制台产品运行入口接入低频会话资源采样。每5秒采集本进程CPU和内存，会话开始与结束补取样；最多保留20000个内存样本，结束时仅将汇总写入schema v6的会话记录。历史摘要可看到CPU平均值、P95和内存峰值，报告导出与性能图表没有加入。

采样初始化或中途失败只写入诊断状态，不改变摄像头、规则、事件和分数。v5→v6迁移会先备份并为历史会话保留空资源汇总；自动测试覆盖迁移、持久化、有界采样和失败隔离。未被局部处理的工作线程异常会把具体原因写入当前会话，同时保存已有资源汇总并释放数据源。
