## 已实现

- product.py：SQLite schema v4与顺序迁移账本、单次任务、SessionService、聚合覆盖、幂等action/扣分、保留与删除、事件截图、单运行实例锁。

- cli.py：新增独立product命令，不更改C的测试入口、视觉模型、阈值、配置、规则实现。
- product读取当前冻结的零扣分软规则。暂停通过现有exempt状态清除计时，保留已扣额度；离席候选期间屏蔽手机规则，避免同时处罚。
- 数据保存在独立产品目录；默认不截图；无报告导出、重复任务、复杂界面或新第三方依赖。

## D1 可升级数据地基启动

项目所有者纠正“D接近收尾”的错误判断后，所有状态文档已改为“早期实施：极简垂直切片已打通”。数据库从只接受单一v1结构推进到带 `schema_migrations` 账本的顺序迁移；未来版本会拒绝打开，迁移在短事务内执行。

升级现在会先按原版本自动生成 `observer.sqlite3.vN.backup`，再逐版本更新结构和版本；迁移出错会回滚，步骤若跳级或未推进会立即失败。当前版本若缺表、缺字段、缺唯一活动会话索引或迁移账本不一致，也会拒绝继续运行。自动测试覆盖带历史数据v1→v2→v3→v4升级、v2和v3的真实字段变更、备份可读、故障回滚和损坏结构拒绝。

目标电脑真实 `data/product` 在首次迁移前已使用SQLite backup API保存 `observer-v1-before-migration-20260910.sqlite3`；迁移前后均为6个会话、1个任务，数据库版本由1升至2并写入两条迁移记录。因为该库在加入自动命名备份前已经完成升级，所以保留的是上述人工命名的v1副本。该结果完成D1的首个“迁移安全基础”切片，不表示数据模型或D主体完成。

## D2 任务与会话可靠性启动

启动审查发现控制台和桌面此前会把所有已经到点的待执行任务立即标为 `missed`，实际绕过了计划中“重启后迟到不超过60秒仍启动一次”的补偿规则。现将过期判断集中为同一存储接口：迟到小于或等于60秒的任务保持可执行，超过60秒才标为错过；桌面回归测试证明迟到30秒的任务会自动补启动、只建立一个会话并正常结束。

控制台恢复路径同时补齐资源释放：若摄像头已重新打开但会话恢复失败，会立即关闭新源，不占用设备。schema v3为任务增加可选错误原因；定时任务启动失败、迟到、冲突和异常中断会保存简短原因，重开桌面后仍能在原计划列表直接看到，不增加页面或设置项。

冲突、失败和错过的任务现在可在无活动会话时立即重试，也可直接取消；已经建立过会话的任务仍禁止重复执行。桌面计划页只增加一个“重试选中任务”按钮，CLI增加 `product retry <任务ID>`。摄像头读取异常不再终止整个桌面或控制台：当前会话保存为 `interrupted`、释放设备，运行入口继续可用。schema v4进一步保存会话中断原因，点击历史摘要仍能查看。

真实摄像头源增加有界断流恢复：短暂无帧继续输出安全 `unknown`；连续约5秒没有新鲜帧后，同一会话最多自动重连一次，只重建摄像头采集线程，复用已经加载的模型和会话校准基线。断流时显式打断规则连续性，间隔计入eligible但不计valid，不能把断流前后的违规片段拼成一次处罚。重连成功继续原会话；失败或再次断流则保存中断原因、释放设备，桌面/控制台仍可开始新会话。全套207项自动测试通过，`pip check` 和 `git diff --check` 通过。D2基本恢复路径已覆盖，更复杂的进程级崩溃恢复仍未完成。
