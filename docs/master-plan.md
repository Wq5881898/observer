# Observer 总体阶段计划与门控

版本：0.6
日期：2026-09-21
状态：已批准；阶段 C、D 已通过并关闭

## 1. 目标

本文件是 Observer 的阶段级基准。它只回答三个问题：当前在哪一阶段、每一阶段交付什么、满足什么条件才能进入下一阶段。具体算法、测试脚本和结果分别记录在阶段文档中。

阶段状态只能是：`未开始`、`规划中`、`实施中`、`有条件通过`、`通过`、`返工`。未经项目所有者确认，不能把阶段自行标记为通过。

## 2. 统一门控流程

每个阶段按同一流程执行：

1. 恢复并核对已有需求、代码和历史决策；
2. 写清目标、范围、非目标、依赖和风险；
3. 比较候选方案并记录选择理由；
4. 定义可量化验收线、测试数据和失败回退路线；
5. 项目所有者批准阶段基准；
6. 按批准基准一次性完成实现、自动化测试和目标设备验证；
7. 形成阶段结果报告，列出偏差、已知限制和遗留项；
8. 项目所有者确认阶段结论后，才能进入下一阶段。

如果实施中需要改变已批准的产品含义、隐私范围、核心依赖或验收线，必须先更新基准并重新确认。普通缺陷修复和不改变行为的内部重构不触发重新立项。

## 7. 跨阶段不变原则

1. 完全本地处理，不上传摄像头图像、校准特征或行为数据；
2. 不录制连续视频，只允许按明确策略保留少量事件关键帧；
3. 不可观测、低质量和设备故障不能形成违规时长或固定扣分；
4. 普通摄像头不宣称专业眼动或医学姿势能力；
5. 感知模型只产生事实和置信度，持续时间、提醒、事件合并和计分由产品规则层决定；
6. 新计分信号通过标准信号与规则注册接入，并由合并层去重，不改写Agenda和会话主流程；
7. 默认运行开销必须服从已批准的 CPU、内存和响应预算；
8. 未达到验收线时公开降级能力或更换路线，不能通过降低测试难度掩盖问题。
