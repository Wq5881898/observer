# E4 单实例窗口唤醒结果

日期：2026-09-22  
状态：代码和自动测试完成；Windows 双击启动实机点验待完成。

## 实现

桌面启动在创建 ObserverWindow、产品工作线程、数据库和摄像头之前，先尝试连接同一数据目录对应的本地唤醒端点。若已有实例确认 `show` 请求，第二次启动立即正常退出，已有实例恢复并激活原窗口。

端点名称由规范化数据目录的 SHA-256 前缀生成；不同数据目录互不影响。服务端使用 Qt `QLocalServer.UserAccessOption`，Windows 下是同机命名管道，只接受精确字节 `show\n`，只返回 `ok\n`。接口不接受开始、暂停、结束、计划、路径、SQL 或摄像头参数，不监听网络端口。

第一实例仍由原 DesktopWorker 获取 RuntimeLock，再创建 ProductStore；本地唤醒只改善常见的重复启动体验，不能替代锁。连接不存在、超时或响应不正确时，启动继续进入原流程，由 RuntimeLock 最终拒绝可能的竞争实例。Windows 允许极窄启动竞争中两个同名管道监听者，运行锁仍保证只有一个数据库/会话/摄像头所有者。

退出时关闭唤醒服务。退出收尾期间第二次启动可能唤醒正在退出的实例并自行结束；用户可在旧进程完全退出后重试，避免在锁释放边界自动创建第二所有者。

实现依据 Qt 官方 [QLocalServer](https://doc.qt.io/qtforpython-6/PySide6/QtNetwork/QLocalServer.html) 和 [QLocalSocket](https://doc.qt.io/qtforpython-6/PySide6/QtNetwork/QLocalSocket.html) 接口。

## 自动验证

专项测试覆盖：精确 show 请求只激活一次、不同数据目录不能连接、服务关闭后拒绝连接、规范化目录得到稳定且隔离的名称、唤醒成功时不会创建窗口或产品工作线程。客户端使用独立 Python/Qt 进程验证真实本地管道往返。

2026-09-22 补强本地管道分段传输：请求分两次到达时仍可完整识别；无效或超长请求拒绝，未完成请求一秒后关闭，避免长期占用连接；客户端在总超时内读取完整确认响应。新增跨进程分段请求测试，全套自动测试 326 项通过。资源管理器第二次启动的人工点验留到 E 集中测试。

完整回归：320 项通过（42.736 秒）。实机仍需从资源管理器或第二终端启动同一命令，确认隐藏窗口恢复且任务、会话、摄像头和历史没有重复；不同 `--data-dir` 应继续允许独立实例。
