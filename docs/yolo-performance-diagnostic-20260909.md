# P7 性能初诊

P7 实时识别 12/12 通过；平均 CPU 21.92475%、P95 33.0625%，超过
15%/25% 预算。CPU 采样已除以逻辑处理器数，口径为整机 0–100%，无需再除。
峰值内存 365.254 MB 低于 500 MB 预算。

现状：摄像头 15fps，face 8fps、pose 4fps、object 1.5fps/突发 5fps；
手机专项仍执行 face/pose。ONNX 会话未配置线程数与空转策略。

新增 scripts/benchmark_yolo_threads.py，使用 P7 review 的三张保存图片，
每图重复四次，每次推理后等待 0.1 秒；不访问摄像头、不修改模型与默认运行配置。
结果见 P7 批次 thread-benchmark.json 和 thread-benchmark-v2.json。

第二轮默认策略总耗时 2.704s，CPU 时间 6.688s；仅关闭线程空转（threads=-1）
总耗时 3.201s，CPU 时间 4.438s，计算工作相同下 CPU 时间下降约 34%，
耗时增加约 18%。三张图重复推理的类别和置信度（保留五位）一致。
第一轮单线程 CPU 时间更低但耗时明显增加，不宜据此降低实时处理能力。

限制：仅三张图片、单进程短测，顺序执行且未控制温度和系统负载；这不是完整
应用资源验收，也不是完整框坐标一致性验证。报告 CPU 百分比受吞吐量变化影响，
优先比较相同工作量的 CPU 时间与总耗时。

下一步：以关闭空转为候选，在固定频率、相同录像和完整感知链路下比较资源消耗、
延迟及规则输出，另区分录像/预览成本。通过后再改变运行默认值；当前没有更换
模型、降低检测阈值或推理频率。本轮无需用户重新标注或重新训练。
## 完整感知链路短测

scripts/benchmark_probe_threads.py 使用 P7 原录像时间戳按时回放 E01 和 F01，
执行 face、pose、YOLO、追踪与融合；不含摄像头、预览、录像编码，不加载个人校准。
每段重新初始化，故 E01 开始有 13 帧合规与真人预热后采样不同。

| 片段 | 默认空转 CPU | 关闭空转 CPU | 手机状态逐帧比较 |
| --- | ---: | ---: | --- |
| 极低下边缘 12 秒 | 35.21% | 19.57% | 136/136 一致 |
| 中央充电宝 10 秒 | 16.89% | 9.27% | 127/127 一致 |

总耗时基本不变（E01 12.159/12.155 秒，F01 10.013/9.986 秒）。
原始结果：P7 批次 probe-thread-benchmark-before-prefilter.json。固定时间戳调度用于控制输入，
不模拟实时处理过慢时摄像头丢帧；仅两段顺序短测，不代表 P95 或长时间性能验收。

据此在 YoloOnnxBackend 创建会话时关闭 intra/inter-op spinning，保持模型、
检测阈值、线程数量默认值及各推理频率不变。极低边缘平均 CPU 仍超过预算，
性能工作尚未完成；下一轮实际运行应再次核对 resources.json 与识别结果。

## 单类别候选框预过滤及复核

在单类别五列输出进入 Python 循环前，用 NumPy 批量过滤低置信度候选，
保持原始候选顺序、float64 阈值比较、坐标转换及 NMS 不变；多类别路径不变。
模型、阈值、推理频率均未改变。新增 8,400 候选的回归用例，与未走预过滤的
多类别等价输入比较完整输出，覆盖阈值相等、浮点边界、同分框及两种输出布局。

再次回放 E01/F01，开启和关闭空转的四组输出均与上次逐帧相同
（每种空转配置 263/263 帧）。当前关闭空转的 CPU 均值分别为 17.99%、9.61%，
上次为 19.57%、9.27%；额外提速不稳定，不能据此断言预过滤明显降低整机负载。
本次原始记录为 P7 批次 probe-thread-benchmark.json。

结论：短回放未发现手机状态回归；尚未完成真实运行资源验收，尤其 E01
平均 CPU 仍高于 15% 预算。后续优先实测资源及是否影响前台使用，不为这次
代码优化重新采集训练数据，也不把短测结果等同于完整功能验收。

## P8 实测与 E01 同输入审计

批次：`data/formal/phone-contrast/P8-s304-performance-manual/tuning-20260909T220554Z-584d4c1c`。
平均 CPU 11.017125%、P95 15.75%、峰值内存 366.05078125 MB，100 次资源采样，
本轮资源预算通过；这不是长时稳定性或严格受控 A/B 结论。
场景 11/12 通过。三处手机均 100% violation，充电宝与清空场景无误报；
E01 仅 64.935% violation，最长连续 3.907 秒，故整体不通过。
报告段级 Precision/Recall=100% 不能代替段内持续性验收。

新增 `scripts/audit_p8_decoder.py`：在相同解码视频帧上，对照默认空转+
移除预过滤的旧解码逻辑，与关闭空转+当前解码逻辑。两组使用相同模型。
154/154 帧完整检测结果相同，模型原始输出最大绝对差为 0。
原始记录：本批次 `decoder-ab-audit.json`。这是特定两处优化的数值对照，
并非恢复整个历史程序、实时调度和追踪状态的端到端比较。

回放直接检出 17/154 帧；最大手机候选分数均值 0.1481、范围 0.0293–0.3364，
常低于固定 0.25 阈值。该比例不是人工标注框匹配的召回率。
视频有压缩且回放每帧检测，不能直接与直播的 64.9% 追踪后比例相比。
独立的实时 derived_samples 记录中，E01 有 100 条采样、46 个不同 object_at，
其中 11 个更新有 raw_phones。它并非全量检测日志，但同样支持检测断续。
采样状态约在 3.985–7.500 秒和 9.141–9.844 秒为 compliant；间断时
raw_phones 与 tracked_phones 都为空，而不是已有手机框被最终状态忽略。

结论：同输入未发现本次性能优化导致数值回归；E01 暴露的是本轮输入下
模型的低置信度/断续检出。具体外观、可见面积、光照与压缩各自的作用尚未
隔离，不能归咎测试者，也不能保证所有实时调度影响已排除。
不重做 12 项，不立即降阈值或延长保留时间，不追加训练。
保留 E01 为未关闭的边缘鲁棒性问题及固定离线回归素材；模型仍是候选，
不得宣称手机功能全面验收完成。若继续改善该边界，应先确认录像中漏检区间
手机确实持续可见，再复用该材料做针对性诊断，避免重复真人采集。
