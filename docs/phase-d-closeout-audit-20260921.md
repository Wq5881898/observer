## 3. 代码核查结果

- 产品数据库当前为 schema v9；关键关系覆盖 `tasks`、`sessions`、`totals`、`actions`、`evidence` 和 `focus_incidents` 六组外键约束。
- 新会话产品规则只有 `away`、`attention_away`、`posture_deviation` 和 `phone_held` 四条；`ergonomic_risk` 只保留为底层研究解释信号，不再形成第二种产品事件。
- 当前持续门槛为离席20秒、离屏10秒、姿态20秒、可见手机10秒；统一姿态恢复2秒、提醒冷却300秒且零计分。
- 新会话使用 `time_ratio_v2`；旧会话继续保留 `points_v1`，不依据缺失的历史区间追溯重算。
- 暂停、计划休息、断流和不可观测状态会切断持续区间；手动暂停冻结剩余时间，计划休息保持固定计划结束时间。
- 正式证据与测试取证均复用事件ID、原子写入、SHA-256、路径边界、保留期和配额管理。

## 5. 本次发现并修正的偏差

1. 总体计划和D开发计划仍把D写为“实施中”，与后续结果报告冲突；现统一为“通过并关闭”。
2. 运行手册仍写“完整负载验收待进行”，但D5真实60分钟门已经通过；现改为历史事实。
3. D/E接口仍写schema v8和五条外键；当前代码实际为schema v9和六组外键，现已更正。
4. 范围复核仍写本次延长和高级计划闭环待点验；这些项目后来已经完成，现已关闭。
5. 需求对照仍把测试取证多图查看列作开放体验项；代码、自动测试和既有界面使用证据足以完成D关闭，现移出D开放项。
6. 正式截图描述仍有“合并专注事件最多一张”的旧说法；当前正式策略为成立事件首尾两张，统一姿态事件最多一张，现已统一。
