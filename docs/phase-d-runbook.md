# D 极简首版使用说明

> E1 已实现托盘与窗口生命周期。本文中“关闭即退出、不驻留托盘、保持窗口打开”的描述保留为 D 基线；当前桌面行为以 [E 使用说明](phase-e-runbook.md) 为准：有可用托盘时关闭仅隐藏，完全退出使用窗口“退出程序”或托盘“退出”。

从项目根目录运行。`Observer`标题下方提供“专注 / 历史 / 高级计划”三个一级页面；重复计划、计划休息、本次延长和今日摘要集中在完整的高级计划页。报告只在界面查看，不导出。

## 图形窗口（推荐）

已安装 PySide6；在新环境中使用 `uv sync --extra desktop --extra yolo` 安装锁定依赖。

```powershell
# 模拟体验：不打开摄像头，使用独立模拟记录
.\.venv\Scripts\python.exe -m observer product --data-dir data/product-demo gui --demo

# 真实观察：点击开始或任务到点后打开摄像头
.\.venv\Scripts\python.exe -m observer product gui
```

填写名称和时长后点“开始”。真实窗口显示后会在后台核对并加载冻结视觉模型，不打开摄像头；用户可同时填写任务和时间。准备完成后消息区显示“视觉模型已在后台准备好”。按钮点击后立即变为“启动中…”并禁用，此时接管预热模型、打开摄像头并完成本次头姿基线；保持自然坐姿并看屏幕中央，进度到3秒后开始观察，期间不会另开摄像头预览窗口，完成或失败前无需重复点击。若打开窗口后立刻开始，则会等待尚未完成的同一预热任务，不重复加载。成功后原消息区显示本次准备耗时，分阶段与总耗时同时写入会话身份供诊断。真实模式每次启动的成功、失败或取消还追加到 `data/product/logs/startup.jsonl`；日志细分模型文件、配置、profile、运行库导入、ONNX会话、MediaPipe、预热等待、摄像头、首帧、环境核对和基线稳定时间，不保存任务标题、图像或视频，超过512 KiB自动轮换一份旧日志。等待时关闭主窗口会取消摄像头启动、首帧等待或基线，并执行有界资源释放。勾选“指定开始时间”后，按钮变成“安排任务”，到点自动开始；保持窗口打开。手动暂停会冻结剩余时间并关闭摄像头，继续时顺延本次结束时间；计划休息仍不改变固定结束时间。专注页下半部分按成立时间显示本轮事件；会话结束后，最近一轮标题行显示最终总分、总违规秒数和有效覆盖，证据不足时不伪造分数。开启截图后，有图事件提供“查看”链接，点击后在同一窗口右侧展开预览；同一事件有多张图时可切换上一张和下一张。完整历史记录点击查看摘要；历史页顶部显示本地记录、任务、事件图片占用、截图状态和保留期，可删除选中的已结束记录或清理过期记录。“高级计划”页可维护重复计划，并在“执行记录”内重试或取消冲突、失败和错过的任务。截图默认关闭，可在窗口勾选开启。

在“高级计划→重复计划”中填写名称、时间、每天/工作日/每周选定星期和时长；可选“每 N 分钟休息 M 分钟”及“允许离屏查看资料”。保存后只滚动生成有限未来任务，保持窗口开启才会到点执行。计划休息期间自动停止连续违规计时、排除计分时长并关闭摄像头，休息结束后自动恢复；休息不延后原结束时间。“允许离屏”只对本次任务豁免离开屏幕计分，离席与可见手机规则继续生效。选中模板可编辑、停用、启用或删除，已完成、错过、冲突和失败记录不被改写。在“执行记录”中可把当前会话延长若干分钟，该修改不回写模板；点击后按钮立即显示处理中并锁定，成功后在原位置显示本次新增和累计延长时间，并短暂阻止连续误点。页首今日摘要显示计划、完成、观察、休息、违规秒数、时间比例得分和覆盖率；同日旧规则扣分会单独标记。时长输入框只编辑数字，“分钟”作为不可编辑的独立单位显示。

模拟模式另有模拟信号选择框，开始后可切换“可见手机”并等待10秒测试提醒。关闭窗口会结束当前会话并标记中断、释放摄像头；不驻留托盘。界面与推理/SQLite分线程，初始化模型期间仍可操作关闭窗口，窗口会等待资源释放完成再退出。

若存在 `data/calibration/default.json`，真实模式默认自动采用；也可用 `--profile` 指定其他档案，或用 `--no-profile` 明确关闭校准信号。界面会显示当前能力。离开屏幕和可见手机连续10秒成立，离席连续20秒成立；三项重叠时合并为一个专注违规事件，同一秒只计算一次，每个合并事件只播放一次明显短音并显示红色横幅和任务栏闪烁。若第一项成立时还有重叠候选，最多等待10秒合并提醒；后来在同一事件中成立的信号只更新记录，不再次发声。原姿态与人体工学候选合并成一个“姿态”信号，偏离个人基线持续20秒形成零计分事件，恢复2秒结束；它使用音量较低、时长约0.12秒的柔和声音和浅色横幅，不闪烁任务栏，横幅约4秒后自动收起。同一会话内5分钟最多发声和显示一次，冷却期间新成立的事件仍保存并标为已记录。会话摘要显示计分时长、合并违规时长、合规时长、时间比例得分及统一姿态累计偏离；累计时间不等于连续触发时间。摘要中的“提醒交付”区分已确认、未确认和无法追溯的历史状态；交付状态不影响分数。单次任务启动失败显示原因，不会静默换模型。

头眼基线失败时，主界面和执行记录只显示可操作的中文说明：“未能完成头眼基线，请正对摄像头，确保完整脸部和双眼可见，并看屏幕中央后重试。”帧数、无效原因计数等完整诊断继续保存在任务错误字段和 `data/product/logs/startup.jsonl`，不在日常界面暴露内部英文实现信息。

启用校准时，任务状态下方同时显示即时“头眼：屏内/屏外候选/不可判断”。下一行显示当前专注干扰信号：“其他事件：发现手机”“其他事件：离席候选”“其他事件：未发现”或相应不可判断状态；手机和离席同时出现时并列显示。这些即时文字只用于理解模型当前看到了什么，不代表事件已经成立，也不改变手机/离屏10秒、离席20秒的门槛、合并提醒和计分。“屏外候选”表示当前观测为violation；“不可判断”不会累计事件时间。产品会话记录实际同会话头姿基线，便于与C受控验证对照。

桌面基础版属于经用户要求提前推进的 E 界面工作；不表示完整 E（完整系统通知、托盘、摄像头进程隔离等）已完成。真实图形窗口的手动开始/关闭中断、单次与重复计划、带profile注意力对照、事件证据和60分钟完整负载门均已通过。D阶段已关闭，后续桌面常驻与发布能力进入E/F。

## 2. 真实运行

```powershell
.\.venv\Scripts\python.exe -m observer product run
```

再输入 `start 25 阅读`。未开始且没有到期任务时不打开摄像头；暂停和结束后关闭摄像头。手动暂停冻结剩余时间，继续时顺延本次结束时间；计划休息不顺延。控制台一直保留，才能执行到期任务。同一产品目录已有桌面或控制台运行窗口时，新运行入口会在打开数据库和摄像头前被拒绝；任务、历史和数据管理命令仍可从另一终端使用。

真实入口在打开摄像头前检查 `models/yolo/observer-phone-s304-e2b.onnx` 的冻结文件大小与SHA-256、完整模型清单哈希和默认配置哈希，并由清单继续验证MediaPipe与低频EfficientDet Person资产，不静默切换模型或参数。任一文件缺失或身份不符时开始失败，不形成违规时间。默认校准档案存在时自动启用attention及统一姿态信号；其中attention参与专注时间评分，统一姿态保持零计分软提示。底层仍计算原posture/ergonomic候选用于合并和解释，但不再生成两个产品事件。profile允许以后重新校准，因此不固定为全局哈希，但每次会话保存实际profile哈希和会话头姿基线。缺失profile或显式使用 `--no-profile` 时，attention不参与计分或有效覆盖，界面明确说明仅启用离席与手机计分信号。硬在席路径仍保留已有无校准姿态可信门。

指定其他已有校准时：

```powershell
.\.venv\Scripts\python.exe -m observer product run --profile data/calibration/default.json
```

路径必须指向本机有效档案；每次打开摄像头会沿用 C 的临时会话基线窗口，不重新做17点校准。档案环境不匹配则开始失败。姿态与健康工学始终零扣分；离开屏幕按上述规则计分。

明确只使用离席和可见手机时：

```powershell
.\.venv\Scripts\python.exe -m observer product gui --no-profile
```

需要快速检查正式产品链路与资源采样时，可运行：

```powershell
# 默认15秒，打开真实摄像头与冻结视觉链路
.\.venv\Scripts\python.exe -m observer product check

# 不打开摄像头，只核对SessionService、SQLite和资源采样接线
.\.venv\Scripts\python.exe -m observer product check --seconds 5 --demo

# D5长期资源门：真实摄像头连续运行60分钟
.\.venv\Scripts\python.exe -m observer product check --seconds 3600
```

检查使用自动删除的临时产品目录，不写入正常历史。短检会显示CPU平均值、P95、内存峰值和样本数，只验证观察、数据库和资源链路，不提供正式的实时提醒通道；事件仍会出现在结束摘要中，交付状态可能显示未确认。几秒至数分钟的结果不能判断每小时内存增长，也不替代60分钟资源门。

只有精确运行3600秒且不带 `--demo` 才启用D5门禁。门禁要求会话正常结束、硬信号有效覆盖不低于80%、资源采样没有错误且至少取得360个样本、能够计算每小时内存增长，并同时满足CPU平均15%、CPU P95 25%、内存峰值500 MB和每小时增长50 MB预算。任一条件不满足都会列出原因并以非零状态退出；通过时也会明确显示每小时内存增长。执行期间应保持电脑接电、关闭其他占用摄像头的程序，并按日常方式使用，不需要故意制造违规动作。

## 3. 一次任务

保持真实运行窗口开启，在另一个终端添加任务（替换为未来实际时间）：

```powershell
.\.venv\Scripts\python.exe -m observer product task "阅读" --at "2026-09-20T09:00:00-06:00" --minutes 25
.\.venv\Scripts\python.exe -m observer product tasks
.\.venv\Scripts\python.exe -m observer product cancel <任务ID>
.\.venv\Scripts\python.exe -m observer product retry <任务ID>
```

时间必须包含UTC偏移。运行中到期60秒内启动一次；程序重启时迟到不超过60秒的pending任务仍补启动，超过窗口记missed。已存在会话则记conflict，模型/摄像头启动失败记failed，并保存简短原因。conflict、missed和failed可重试或取消；已经建立过会话的任务不会重复执行。当前不提供编辑，取消后新建即可。暂停中的会话同样占用唯一会话位置。

不同数据目录是不同任务列表；模拟任务请在命令中使用相同 `--data-dir data/product-demo`。

## 4. 历史与隐私

```powershell
.\.venv\Scripts\python.exe -m observer product history
.\.venv\Scripts\python.exe -m observer product data
.\.venv\Scripts\python.exe -m observer product show <会话ID>
.\.venv\Scripts\python.exe -m observer product images on
.\.venv\Scripts\python.exe -m observer product images off
.\.venv\Scripts\python.exe -m observer product delete <会话ID>
.\.venv\Scripts\python.exe -m observer product purge
.\.venv\Scripts\python.exe -m observer product delete-all
```

摘要显示状态、总分或证据不足、覆盖率、计分/违规/合规时长、合并事件、各分项累计及本次会话的CPU平均值/P95和内存峰值。新会话按 `(计分时长-总违规时长)/计分时长×100` 评分；暂停和计划休息不进入计分时长，成立信号的重叠区间只算一次。任一当前计分信号覆盖低于80%不展示有效总分，底层区间仍可查。没有观测不能得到有效100分。旧会话继续显示当时的固定扣分分数，并标记为旧规则。资源数据每5秒低频采样，短会话只用于确认采样接线和发现明显异常，不能代替60分钟资源门。若单条旧记录的身份或资源汇总损坏，列表与其他记录仍可使用，该条会显示“身份异常”或“数据警告”，可按普通已结束记录删除。

`product data` 与历史页顶部显示同一本地统计。截图默认关闭。开启截图、关闭测试取证时，已成立的合并专注事件保存候选首帧和恢复帧；未成立候选不落盘。再开启“测试取证（违规期间每2秒截图）”后，从候选开始到全部相关信号恢复每2秒最多保存一张，未达到门槛的候选也保留供分析；重叠信号共用同一序列。统一姿态事件最多一张，不记录连续视频或正常时段。每次运行取得单实例锁后会核对事件图写入中间状态：已完成图片补写哈希，未完成临时文件被清理并标记异常，缺失或哈希不符也明确计入证据异常。每次运行启动及每小时按30天清理已结束会话；也可手动purge。某条过期记录的路径或文件删除失败时，该记录保留并计入证据异常，其余安全记录继续清理，不会停止观察。配额满、没有新鲜帧、路径异常或编码失败同样显示为证据异常，不撤销事件。单次删除同时处理图片及临时文件，失败保留索引供重试。delete-all要求先退出运行窗口；若仍在运行，会在打开数据库和执行任何删除前拒绝。开始删除前还会预检所有证据路径，路径越界时整批保持不变。成功后删除所有产品会话、图像及任务，保留设置和数据库结构。

默认产品目录为data/product。所有删除命令都不操作C的formal、natural、training或模型目录。不要将研究目录用作产品数据根目录。

## 5. 已知限制

### 短真人集成检查（环境合适时）

关闭其他Observer运行窗口和占用摄像头的程序；先确认测试环境合适，再运行 `product gui`。任务设置1分钟，正常坐在屏幕前，点击开始；约10秒后暂停，确认摄像头关闭，再继续。可以提前结束，或等待到时结束；点击历史检查记录为已结束、摘要可见。正常会话不应出现离席/手机硬处罚；覆盖不足应诚实显示证据不足。

此轮默认不开截图、不录视频、不要求故意做违规动作。记录窗口是否卡顿、暂停是否释放摄像头、恢复是否成功、结束是否保存。它只验证产品联通性，不替代C盲测或60分钟性能门。

- 一个桌面或控制台运行窗口控制当前会话，尚无托盘、原生通知或跨终端暂停接口；
- 摄像头启动失败不会自动反复重试，可在计划页手动重试；运行中连续约5秒没有新鲜画面时，同一会话自动重连一次。重连期间计为不可观测且不连接前后的违规计时；恢复后继续原会话，失败或再次断流则保存为interrupted、释放摄像头并保留运行窗口；
- 强制退出后，会话在下次run标记interrupted；已经持久化的违规区间保留，不补算停机时间。真实子进程强制终止回归已验证运行锁会由操作系统释放；
- 聚合观测每秒或有事件时提交，异常崩溃最多丢失末尾约1秒未提交聚合值；
- 产品数据库写入失败会停止本次计分、回滚未完整提交的动作并中断会话，不会继续生成无法落库的处罚；
- 启动时若SQLite快速完整性、外键数据或定义、表字段、连续迁移账本、单会话唯一约束、截图开关或保留期检查失败，产品会在打开摄像头前拒绝运行并显示原因；
