日期：2026-10-10（America/Denver）
状态：实施中；首轮内部候选及自动验证已完成，见[结果报告](phase-f-result-20261010.md)；阶段尚未验收。

## 范围与布局

采用 Windows x64 / Python 3.11 / PyInstaller onedir。先诊断入口，再无控制台入口；两个 EXE 共用同一份 `_internal` 运行库和模型。冻结入口默认打开 GUI，诊断入口保留显式 CLI 参数。只收集锁定运行依赖、必要原生库、原字节默认配置和四个冻结模型及 manifest。

冻结程序的资源从包内绝对位置读取，与工作目录无关。默认产品目录为 `%LOCALAPPDATA%/Observer/product`，校准为 `%LOCALAPPDATA%/Observer/calibration/default.json`；源码入口沿用当前默认值。显式参数优先，不迁移现有数据。全部测试显式使用隔离目录。启动错误写入用户目录的本地有界日志；窗口版不能仅写 stdout/stderr。

构建工具单独锁定于 `packaging/`；独立构建环境位于忽略的 `build/`，从 `uv.lock` 安装 desktop/yolo 依赖，不修改源码运行环境。版本、锁文件、打包输入、源文件摘要、冻结资源摘要和实际依赖写入构建记录。冻结会话注明摘要来自构建记录，不能把空目录摘要当作源码身份。

## 实施及验收

1. 复核模型、依赖和工作区，加入路径、入口、身份和错误处理回归；运行完整现有测试。
2. 添加受控 spec、构建脚本和最短启动说明；使用新的构建输出目录，保留旧证据。
3. 构建诊断/GUI 候选，记录全部文件哈希及第三方许可信息和未审查项。
4. 在隔离数据及中文/空格路径、任意工作目录、去除开发 PATH/PYTHONPATH 的子进程中验证冻结资源和原生库。无摄像头地加载视觉模型，不打开采集设备。
5. 以候选内部 Qt/产品集成冒烟验证模拟开始、暂停、继续、结束、历史重读、设置持久化、单实例唤醒及退出释放；记录 UI/通知/声音只能自动验证的范围。
6. 仅对候选副本注入缺资源错误、执行目录替换/回退和数据保护验证，检查包内无数据库、个人校准、图像、日志、开发秘密和测试注入脚本。
7. 形成 F-P1～F-P10 结果表，将真实桌面人工点验、干净机器验证以及 E 两项遗留如实留待测。完成便携验证前不展开安装器。

E 保持实施中（补验暂缓）；不启动摄像头补验、长测、设备切换或重启。F 内部候选不等于正式发布，不改变评分、schema、规则、模型及隐私边界。公开分发前另审查依赖及模型许可。
