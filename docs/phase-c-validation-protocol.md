# Observer 阶段 C 校准与验证协议

版本：0.2
日期：2026-08-30
状态：已批准；用于 `docs/phase-c-baseline.md`

## 1. 协议目的

本协议把“看起来能检测”变成可重复的个人目标设备验证。实施代码不得在运行留出集之后继续修改阈值；需要调整时，旧留出结果作废，建立新的留出批次重新运行。

## 2. 固定测试环境

每批记录以下环境信息：

- 电脑型号、Windows 版本和电源模式；
- 摄像头索引、后端、分辨率、目标 FPS；
- 主屏分辨率、缩放比例和窗口/全屏状态；
- 大致光照类别：正常、偏暗、强逆光；
- 是否佩戴眼镜、口罩或帽子；
- 手机型号/外形说明和手机壳；
- Observer 提交 SHA、配置哈希、模型清单哈希和校准档案 ID。

环境字段只用于本地复现，不记录姓名。主验收环境固定后，不能在留出集中途改变摄像头位置、屏幕布局或座椅高度。

## 3. 隐私与文件规则

- 摄像头帧默认仅在内存中存在；
- 数值记录写入 `data/validation/<batch-id>/`，该目录不进入 Git；
- 不保存完整 landmarks，只保存验证所需派生指标；
- 若批准 `errors` 证据策略，只在误判/边界 trial 保存一张代表帧；
- 证据文件名使用随机 ID，不含姓名、场景文字或时间以外的身份信息；
- 每张证据记录 SHA-256、对应 trial 和计划删除时间；
- 阶段结果报告只提交聚合指标，不提交图像和个人校准档案。

## 4. 数据集隔离

每类能力建立两批互不重用的 trial：

- `tuning`：用于发现问题和选择阈值；
- `holdout`：阈值冻结后用于最终验收。

同一个实际动作不能复制到两个数据集。重新调参后必须创建新 holdout 批次，不能反复看同一留出集直到通过。

## 5. 校准流程

### 5.1 通用预检

1. 运行环境诊断、模型 SHA-256 校验和摄像头打开测试；
2. 显示取景引导，确认整张脸、双眼、双肩和至少一侧手腕可见；
3. 检查亮度、模糊和模型新鲜度；
4. 连续 5 秒质量合格后才能进入校准；
5. 中途质量丢失超过 3 秒则暂停，而不是把缺失样本写入档案。

### 5.2 姿势校准

1. 用户采用真实可持续的舒适中立坐姿；
2. 前 5 秒用于稳定，不进入统计；
3. 后续采集 30 秒，目标至少获得 75 个有效 Pose 样本和 150 个有效 Face 样本；首次真实校准发现 25 秒在实际 UI 负载下余量不足，因此延长时间而不降低样本门槛；
4. 若有效覆盖率低于 90%，校准失败并说明原因；
5. 对每个特征保存中位数、MAD、P05/P95 和样本数；
6. 立即进行 10 秒中立复测，若被判偏离的时间超过 10%，档案拒绝保存。

### 5.3 注意力校准

1. 使用主屏全屏依次显示 9 个点：中心、四边中点和四角安全内缩位置；
2. 每点先稳定 1.5 秒，再采样 2 秒；质量下降时该点重做；
3. 使用虹膜/眼眶相对位置、头部方向、脸部位置和尺度构建特征；
4. 拟合后显示未参与拟合的验证点；
5. 保存训练误差、独立验证误差和有效样本覆盖率；
6. 若边缘验证点持续失败，档案不能仅因中心点准确而通过。

## 6. Trial 通用规则

- 每个 trial 开始前显示动作说明；
- 用户确认准备后开始记录；
- 前后各保留短暂缓冲，但只按人工标记区间计算真值；
- positive trial 的目标动作保持到规定结束；
- negative trial 不应被迫做不自然动作；
- 预测、人工标签和计时使用单调时钟；UTC 仅用于审计；
- 任何中断、说明执行错误或设备变化的 trial 标记为 `invalid`，不得挑选为正确样本。

## 7. 场景矩阵

以下重复数分别适用于 tuning 和 holdout。核心场景每批至少 5 次，质量/异常场景每批至少 3 次。

### 7.1 在席与质量门

| 场景 | 真值/期望 | 每批重复 |
| --- | --- | ---: |
| 正常坐在屏幕前 | present/compliant | 5 |
| 完全离开座位 | away/violation | 5 |
| 只露出部分脸但上半身清晰 | present 或可解释 unknown，不得 away | 3 |
| 遮住摄像头 | unknown | 3 |
| 偏暗/逆光 | unknown 或降低置信度，不得违规 | 3 |
| Face 短暂丢失但 Pose 存在 | present | 3 |

### 7.2 手持手机

| 场景 | 真值/期望 | 每批重复 |
| --- | --- | ---: |
| 画面中没有手机 | compliant | 5 |
| 手机放在桌面且手远离 | compliant | 5 |
| 短暂拿起后放下 | 瞬时 held；不得形成超时事件 | 5 |
| 单手持续手持 | held/positive | 5 |
| 双手持续操作 | held/positive | 5 |
| 手持并低头看手机 | held/positive；可额外记录 use_suspected | 5 |
| 手机局部遮挡但仍在有效区域 | positive 或可解释 unknown | 3 |
| 手机和双手位于画面下方 | unknown，不得 compliant 恢复 | 3 |
| 手持遥控器/计算器 | compliant | 各 3 |
| 手持黑色笔记本或相似矩形物 | compliant | 3 |

### 7.3 姿势

| 场景 | 真值/期望 | 每批重复 |
| --- | --- | ---: |
| 中立坐姿与正常打字 | compliant | 5 |
| 正常伸展后恢复 | 不形成持续事件 | 5 |
| 持续明显前倾/离屏幕过近 | violation | 5 |
| 持续左倾 | violation | 5 |
| 持续右倾 | violation | 5 |
| 持续塌肩/头部前伸 | violation（在关键点可观测时） | 5 |
| 肩部被遮挡 | unknown | 3 |

### 7.4 屏幕注意力

| 场景 | 真值/期望 | 每批重复 |
| --- | --- | ---: |
| 看屏幕中心、四边和四角区域 | compliant | 每区域 3 |
| 正常打字时短暂看键盘 | 瞬时 away；不得形成超时事件 | 5 |
| 短暂扫视左右后立即返回 | 不形成持续事件 | 5 |
| 持续看屏幕左外侧 | violation | 5 |
| 持续看屏幕右外侧 | violation | 5 |
| 持续看屏幕下方/桌面 | violation | 5 |
| 闭眼、揉眼或手遮眼 | unknown | 各 3 |
| 常用眼镜状态 | 按实际日常状态重复主场景 | 同主场景 |

## 8. 指标计算

### 8.1 事件匹配

人工 positive 区间与预测 active 区间有有效重叠，且预测启动时间不早于允许的预触发容差，记为 true positive。一个人工事件最多匹配一个预测事件；重复告警不增加 true positive 数。

- `precision = TP / (TP + FP)`；
- `recall = TP / (TP + FN)`；
- `F1 = 2PR / (P + R)`；
- 误报率按没有人工违规的有效观测小时计算；
- 延迟误差按“预测启动时间 - 人工成立时间 - 配置触发时长”计算；
- 有效观测覆盖率按 compliant/violation 的时间除以计划观察时间计算，exempt 单独报告。

### 8.2 汇总要求

报告同时给出：

- 事件混淆矩阵和 precision/recall/F1；
- 每个场景的 trial 数、invalid 数和 unknown 比例；
- P50/P95 告警计时误差；
- 每小时误报；
- CPU 平均/P95、峰值内存和一小时内存变化；
- 各模型运行频率、平均/P95 延迟和丢帧/积压情况；
- 误判类别，不只给总分。

## 9. 验收执行顺序

1. 自动化测试和静态配置校验；
2. 目标设备摄像头与模型预检；
3. 建立校准档案；
4. 运行 tuning 场景并修复/调参；
5. 冻结配置、校准档案和代码提交 SHA；
6. 运行全新 holdout 场景；
7. 运行 60 分钟正常工作负载，不主动制造违规，用于误报和资源指标；
8. 生成机器可读 JSON 报告和 `docs/phase-c-result.md`；
9. 对照阶段硬门槛给出通过、有条件通过、返工或换路线结论。

在步骤 8 与 9 之间，必须完成 `docs/phase-c-validation-handoff.md`：对可疑复杂设计使用已有派生数据做关闭/简化后的对照，记录指标变化和维护成本。不得为了证明设计有用而改变人工标签或 holdout 场景。

## 10. 中止条件

出现以下情况立即中止当前批次，不把结果混入验收：

- 摄像头被其他程序占用、设备断开或帧时间戳倒退；
- 校准环境指纹变化；
- 持续低质量导致有效覆盖率预计无法达到 90%；
- 用户没有按 trial 说明执行或人工标签错误；
- 电脑过热、进入睡眠/锁屏或电源模式在批次中改变；
- 程序保存了未获批准的图像或连续视频。

中止必须保留原因和已完成 trial 的状态，但无效 trial 不进入 precision/recall 分母。
