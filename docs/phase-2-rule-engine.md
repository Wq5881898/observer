# Observer 第二阶段：Observation 与规则核心

日期：2026-08-29  
状态：核心实现完成，29项自动化测试通过；真实手机正样本和校准功能待接入

## 1. 本阶段结果

视觉模型和产品规则已经解耦：Face、Pose、Object只产生事实信号，统一 `Observation` 再交给规则引擎。规则引擎不导入OpenCV或MediaPipe，因此可以完全用合成时间序列测试。

```text
Face/Pose/Object
      │
      ▼
ObservationFusion
      ├─ away
      ├─ phone_held
      ├─ attention_away（等待个人校准）
      └─ posture_deviation（等待个人校准）
      │
      ▼
SustainedRule → action → alert / PenaltyLedger → score
```

## 2. 四种信号状态

| 状态 | 含义 | 是否累计违规时间 |
| --- | --- | --- |
| `compliant` | 当前明确符合规则 | 否，并进入恢复计时 |
| `violation` | 当前明确违反规则 | 是 |
| `unknown` | 低光、遮挡、结果过期、模型缺失等无法判断 | 否；不能扣分 |
| `exempt` | 计划休息、任务豁免、用户明确暂停等 | 否；立即结束当前规则事件 |

缺少某个信号时默认返回 `unknown`，不会被误解释成违规。

## 3. 手机手持融合

EfficientDet只负责给出手机框和置信度；Pose提供左右手腕坐标和可见度。当前融合逻辑为：

1. 没有检测到手机：`compliant`；
2. 检测到手机，但手腕不可见或Pose结果过期：`unknown`；
3. 手机框到至少一个高可见度手腕的归一化距离不大于0.12：`violation`候选；
4. 手机可见但远离手腕：`compliant`。

所以“桌面上出现手机”不会直接扣分。只有手持候选持续超过配置时间，规则状态机才触发事件。距离0.12是待真实样本验证的起始参数，不是最终产品常量。

## 4. 持续规则状态机

每个规则独立经历：

```text
clear → pending → active → recovering → clear
```

- `pending`期间不足触发时长就恢复，不产生事件；
- `active`时生成激活、提醒和扣分请求；
- 短暂恢复需要连续达到恢复时长才结束事件，防止逐帧抖动；
- `unknown`不增加违规时长；超过未知宽限期后以`observation_lost`结束事件，不追加扣分；
- 相邻观测间隔过大时打断连续计时，程序卡顿不能被算成用户持续违规；
- 提醒有冷却时间，重复扣分有间隔和单项会话上限。

## 5. 当前默认规则

这些值位于 `src/observer/default_config.json`，都是可调整的MVP起始值：

| 规则 | 触发时长 | 首次扣分 | 单项会话上限 |
| --- | ---: | ---: | ---: |
| 离席 `away` | 20秒 | 3 | 15 |
| 注意力离开 `attention_away` | 8秒 | 3 | 15 |
| 姿势偏离 `posture_deviation` | 20秒 | 2 | 10 |
| 手持手机 `phone_held` | 10秒 | 5 | 25 |

默认恢复时长2秒、未知宽限3秒、提醒冷却30秒；手机持续事件每额外60秒申请再扣2分。总分默认从100分开始，不低于0分。最终阈值必须由个人验证和产品设置决定。

## 6. 可扩展性

新增规则只需要：

1. 新的检测器或系统适配器产生一个命名信号；
2. 在JSON中注册对应的 `RuleConfig`；
3. 如需新的解释文本，在UI层增加显示映射。

规则引擎、扣分账本、会话分数和证据流程不需要因为新增规则而重写。规则ID强制唯一，单项上限由账本统一执行。

- 未安排手机正样本，因此手机信号为`compliant`；
