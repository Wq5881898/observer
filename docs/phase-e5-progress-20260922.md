# E5 后台验收进度

日期：2026-09-22  
状态：自动化、隐私挡板和修复后 15 分钟真实负载通过；项目所有者决定不再追加分钟级资源门，先完成功能修复，后集中实机测试或抽检。睡眠/设备掉线和原生通知点验待完成。

## 验收入口

新增 `scripts/run_e5_background.py`。它使用临时产品目录启动真实 Qt 桌面和冻结视觉链路，开始会话后隐藏窗口，按秒记录 CPU、内存、线程和句柄；结束后验证摄像头为空、正常会话状态、桌面退出耗时及 RuntimeLock 可重新获取。测试默认不保存图片或视频，不写入正常产品历史。

脚本遵守产品线程边界：首轮冒烟曾从主线程读取工作线程 SQLite，SQLite 立即拒绝。脚本已改为工作线程退出后新建独立连接读取结果，产品代码未因测试绕过线程约束。

## 隐藏刷新优化

首轮 60 秒后台冒烟 CPU 平均 17.7%，超过 15% 预算。原因之一是窗口隐藏后仍每 0.5 秒构造完整历史/任务快照并更新控件。现由主线程通过既有命令队列发布可见性，隐藏时仅把 UI 快照刷新降到每 5 秒；观测、规则、计分、证据、计划与资源采样频率均不变。恢复窗口后回到 0.5 秒。

优化后的 60 秒结果：CPU 平均 14.807%、P95 18.750%，产品采样平均 13.758%、P95 16.875%，内存峰值 463.625 MB；摄像头释放、会话 ended、运行锁释放均通过，退出 0.516 秒。

## 60 分钟失败定位与启动修复

2026-09-22 完成第一轮 E5 真实后台 60 分钟门。CPU 平均 12.630%、P95 17.575%、内存峰值 460.445 MB 均通过，摄像头、会话和运行锁释放通过，退出耗时 0.547 秒；但产品内存从约 351 MB 增到 460 MB，首尾口径为 109.317 MB/小时，命令按门禁正确返回失败。

分钟曲线把增长集中在首分钟：0 秒 350.906 MB、60 秒 451.223 MB，之后 59 分钟保持约 452～469 MB；线程 63→60、峰值 69，句柄 1093→1126、峰值 1166，没有持续单调增长。根因是无校准档案路径在模型对象加载后立即开始会话和资源计时，原生执行器的首批推理缓存仍在会话内分配；带校准路径已有约 3 秒连续基线推理，因此 D 阶段未暴露同一偏差。

修复保持全部资源阈值不变：`CameraSource` 现在对所有真实摄像头启动先取得首帧并执行三模块推理；无校准档案时再用新鲜帧完成可取消的 3 秒视觉稳定期，然后才创建会话并启动资源追踪。该阶段不计入学习时间、不保存画面，且与校准路径的启动准备语义一致。新增回归保证无档案路径也在 ready 前调用首帧推理。

修复后的 60 秒实机冒烟中，内存从 450.695 MB 到 450.562 MB，消除了原来的首分钟跃升；产品采样 CPU 平均 14.850%、P95 21.338%、峰值内存 450.570 MB 均通过。外层每秒 CPU 平均 16.142% 在短样本中超过 15%，因此该轮仅作为启动内存诊断，不作为长时资源通过证据。

## 内置摄像头开关点验

目标电脑的摄像头不可插拔，机身提供左右隐私开关。新增 `scripts/run_e5_camera_switch.py`，仅在内存中统计新鲜帧、亮度和驱动错误，不保存任何画面。2026-09-22 实测：

| 阶段 | 新帧 | 平均亮度 | 读取失败 | 驱动状态 |
| --- | ---: | ---: | ---: | --- |
| 开关打开基线 15 秒 | 192 | 140.206 | 0 | opened |
| 开关关闭 15 秒 | 160 | 36.773 | 0 | opened |
| 重新打开 12 秒 | 148 | 144.503 | 0 | opened |

关闭时帧流没有中断但画面显著变暗，重新打开后亮度和新鲜帧恢复，测试退出后摄像头已释放。因此该硬件是物理遮挡/隐私挡板，不是设备断开；它通过了“镜头遮挡后可继续、恢复后可观测”的硬件点验，但不能替代设备掉线/自动重连验收。原始结果见 `artifacts/phase-e/e5-camera-switch-20260922.json`。
